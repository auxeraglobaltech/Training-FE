1 · Introduction & Scope

This document specifies the integration and harness built around the lowRISC Ibex 32-bit RISC-V core for simulation-based verification. Ibex itself is an established, in-order core; the subject here is our configuration of it, the OBI memory interface, the simulation memory model, and the end-of-test mechanism — everything needed to run real firmware on the core and check the result. The verification environment is described in the companion Verification Plan.

The DUT is instantiated as ibex_top in tb/top/tb_top.sv and driven by a UVM environment plus a bare-metal C program loaded into simulation memory.

2 · Core Configuration

The core is instantiated with a deliberately simple baseline (chosen to keep the first bring-up small; features such as PMP, ICache, and the writeback stage are enabled later per the verification roadmap).

ParameterValueMeaning
RV32MRV32MFastSingle-cycle-ish multiply / fast divide enabled
RV32BRV32BNoneBit-manipulation extension off
RegFileRegFileFFFlip-flop register file
SecureIbex0No lockstep / hardening (reduces complexity)
ICache0No instruction cache (direct to prefetch buffer)
ICacheECC0No cache ECC
WritebackStage02-stage pipeline (no writeback buffer)
PMPEnable0Physical Memory Protection off by default

Resulting supported ISA: RV32IMC (base integer + multiply/divide + compressed), plus the M-mode CSRs (Zicsr). The boot address is 0x0000_0000 and hart_id is 0.

3 · Pipeline Overview

With WritebackStage=0, Ibex is a 2-stage in-order pipeline.

4 · Integration / Harness

The harness wraps the core with a clock, reset, a single-array memory model, and the end-of-test monitor. The core's two OBI ports connect to the memory model; interrupts and debug are held idle by the UVM driver.

5 · OBI Memory Interface

Each port (instruction and data) follows the Open Bus Interface handshake: the core asserts req with an address; the memory asserts gnt to accept the request; one or more cycles later the memory returns rvalid with rdata. The harness models a zero-wait-state memory: gnt is combinational with req, and rvalid/rdata are registered exactly one cycle after grant.

SignalDir (core)Meaning
instr_req / data_reqoutRequest valid
instr_gnt / data_gntinRequest accepted (address phase done)
instr_addr / data_addroutByte address
data_we, data_be[3:0]outWrite enable, byte strobes (data port)
data_wdataoutWrite data
*_rvalidinResponse valid (data phase)
*_rdatainRead data
*_errinBus error (tied 0 in this harness)
The registered response keeps the core's own bus assertions happy: rvalid/ rdata are stable, known, and arrive exactly one cycle after grant. Wait-state and back-pressure variations are a planned UVM-driven extension (see the Verification Plan).

6 · Memory Map

RegionRangeUse
Instruction ROM0x0000_0000 – 0x0000_FFFFCode + rodata (64 KB)
Data RAM0x0001_0000 – 0x0003_FFFFStack + BSS + data
tohost0x0001_0000End-of-test register (write 1 = pass)
UART TX0x0002_0000Character output register

The reset vector is 0x0000_0000 (start of ROM). The linker script (sw/link.ld) places .text/.rodata in ROM and .data/.bss in RAM, with the stack at the top of RAM.

7 · Memory Model (tb_top.sv)

  • A single byte-addressed array (mem_b[0:262143], 256 KB) covers the whole map; it is zeroed then loaded with $readmemh from the test's .vmem at time 0.
  • Instruction port: combinational gnt, registered 1-cycle rvalid/word read; reset clears rvalid.
  • Data port: same protocol; writes are byte-enabled and applied write-before-read so a same-cycle read-after-write sees the new data.
// little-endian word read
function automatic logic [31:0] read_word(input logic [31:0] addr);
  logic [31:0] a = {addr[31:2], 2'b00};
  return {mem_b[a+3], mem_b[a+2], mem_b[a+1], mem_b[a+0]};
endfunction

8 · tohost / UART Mechanism

The harness uses the standard RISC-V test-termination convention. When firmware finishes it writes a value to the fixed address 0x0001_0000. The harness watches every data-bus write to that address:

A write to the UART TX register (0x0002_0000) is the character-output path used by uart_puts() for simple printf-style tracing.

9 · Interrupts & Debug

The core exposes the standard RISC-V interrupt lines plus Ibex fast locals and an NMI, and a debug request. In the current harness these are driven idle by the UVM reset driver; asserting them at controlled times is a planned hybrid (C + UVM) capability.

LineMeaning
irq_software (MSIP)Software interrupt
irq_timer (MTIP)Timer compare match
irq_external (MEIP)External interrupt controller
irq_fast[14:0]15 fast local interrupts
irq_nmNon-maskable, highest priority
debug_reqEnter debug mode (halt)

10 · Software Image

Firmware is bare-metal C compiled for the core and loaded into memory. The boot sequence is in sw/crt0.S: set the stack, clear BSS, disable interrupts (mie=0), call main(), then write tohost=1 and halt.

// sw/tests/hello_world.c
int main(void) {
  uart_puts("Hello from Ibex!\n");
  volatile unsigned int *tohost = (volatile unsigned int *)0x00010000;
  *tohost = 1;                 // signal PASS
  return 0;
}

The build (sw/Makefile) produces an .elf, a .vmem (loaded by the memory model), and a .dis disassembly for PC tracing against waveforms.
