1 · Goals

Verify that the configured Ibex core (see the Design Specification) executes real firmware correctly and obeys its bus, trap, and CSR contracts. The environment is a training platform: it starts from a minimal, working "run a C program and check the result" loop and grows feature by feature toward full CPU verification. This document states both what is implemented today and the planned feature coverage.

2 · UVM Testbench Architecture

A single Ibex agent observes the bus; a scoreboard checks the end-of-test signal; the memory model and tohost monitor live in tb_top. Stimulus is primarily the C program executing on the core; the UVM driver supplies reset and (later) interrupt/debug timing.

3 · Components

ComponentRole
ibex_ifInterface carrying every DUT signal (OBI ports, IRQs, debug).
ibex_driverActive: releases reset after 10 cycles; holds interrupts/debug idle (the hook for future interrupt/debug timing).
ibex_monitorPassive: taps the data bus and publishes the value written to tohost (0x10000).
ibex_scoreboardChecks the tohost value: 1 = PASS, anything else = FAIL (uvm_error).
ibex_agent / ibex_envStandard agent (driver+monitor) and env (agent+scoreboard) wiring.
ibex_base_testBuilds the env, fetches the vif, runs for a bounded time.
memory model + tohost monitorIn tb_top: serve both OBI ports and end the test on the tohost write.

4 · Test Methodology — C, UVM, or Hybrid

Each method has a specific role; choosing the right one per feature is the core skill this platform teaches.

MethodWhat it isBest for
Pure CBare-metal firmware the core executes like real software.ISA correctness, CSR read/write, exception handlers, PMP config, cache performance.
Pure UVMA sequence drives bus signals directly.OBI protocol, wait-states/back-pressure, bus error injection — conditions software cannot create.
Hybrid (C + UVM)C runs on the core while UVM controls the environment, synchronised via a memory flag.Interrupt timing/latency, cache ECC injection, PMP fault + bus check, debug halt/resume, WFI wakeup.
Synchronisation pattern: C writes a flag to a known address → the UVM monitor sees it on the data bus → the sequence fires stimulus (e.g. asserts an interrupt) → the C handler runs and writes the result to tohost → the scoreboard checks value and timing.

5 · Implemented Today

Working end-to-end smoke: hello_world.c boots on the core, prints over the simple UART, writes tohost=1; the harness detects the write and the scoreboard reports PASS. This exercises reset, instruction fetch, the 2-stage pipeline, loads/stores over the data OBI port, and the end-of-test flow.

Coverage typeTarget

Branch90%+

Enable in Xcelium with -coverage all in the run options; the Ibex RTL ships with its own bus, pipeline, PMP, and cache assertions that should all fire in regression.

8 · How to Run

Prerequisites: Cadence Xcelium with UVM, the RISC-V GCC toolchain (riscv32-unknown-elf-gcc), and the Ibex submodule (git submodule update --init --recursive). From the sim/ directory:

make sim                          # build SW + run hello_world, no waves
make sim WAVES=1                  # + dump waveforms
make sim SEED=12345 WAVES=1       # fixed seed for reproducibility
make sim TEST=isa_arithmetic      # run a different C test
make sim TEST=irq_test TEST_NAME=irq_test   # different C image + UVM test class
make clean                        # remove build + run artefacts

Each run creates runs/run_<timestamp>_seed<N>/ containing xrun.log, the .vmem image, the .dis disassembly, and (with WAVES=1) waves.shm. Check the result:

grep -E "PASSED|FAILED" runs/run_*/xrun.log | tail -3

9 · Adding a New Test

  1. Write the C test sw/tests/<name>.c: run logic, then write tohost=1 on pass (or a non-1 code on fail).
  2. Build & run: make sim TEST=<name>.
  3. (Optional) UVM test class tb/tests/<name>_test.sv for environment control (interrupt timing, error injection); include it in ibex_pkg.sv and run with TEST_NAME=<name>_test.
  4. Debug a failure: grep the log for the failing PC, look it up in the .dis, and open the waveform at that time.
// minimal C test skeleton
int main(void) {
  int pass = 1;
  if (5 + 3 != 8) pass = 0;
  *(volatile unsigned int *)0x00010000 = pass ? 1 : 2;   // tohost
  return 0;
}
