1 Scope & Status

This curriculum teaches CSR access, interrupt handling, and M/U privilege switching on Ibex through phased C testcases — each one exercising a specific piece of the RISC-V privileged architecture via the UVM testbench built around ibex_top. Phases run in order because each later phase depends on infrastructure the earlier ones establish.

2 DV Architecture

The C program on the core is the primary stimulus source — this is a software-driven verification environment, not a bus-level UVM sequence environment. UVM supplies the scaffolding (reset, the one dynamic piece of stimulus the C code can't generate itself — interrupt pins — and pass/fail checking); the test logic itself lives in C.

Why a mailbox instead of a UVM sequence/sequencer: the C program is already the scenario author (it decides when and which interrupt to request); routing that through a sequencer would just add indirection without adding control. ibex_driver.sv taps the bus passively — the same pattern ibex_monitor.sv already used for tohost — and exposes a single poke_irq(line_id, on) task so a future OBI back-pressure sequence can drive the same lines later without touching the irq-state bit logic.

3 Shared Infrastructure (Phase 0)

Trap vector table

Ibex hardwires mtvec[7:0] to 0b00000001 on every write (boot-time or explicit csrw) and passes mtvec[31:8] through unrounded (RTL/ibex/rtl/ibex_cs_registers.sv). Dispatch is hardwired, not read from the mode field: synchronous exceptions always go to base+0; interrupts go to base + 4*mcause[4:0] (ibex_if_stage.sv). sw/link.ld places trap_vectors at a linker-enforced 256-byte boundary for exactly this reason — an unaligned target would silently truncate the effective base below the real table.

CauseValueSlot address

All 32 slots just j trap_common — one shared handler, same mental model as the original single-entry design, with the routing actually correct.

trap_common contract

This is the single most important rule in the whole curriculum: trap_c_handler() must communicate the resume PC via its return value, never via write_csr(mepc, ...). trap_common snapshots mepc/mstatus to the stack before calling C (so a nested trap can't corrupt the outer handler's return state — needed for the Phase 4 nesting test) and unconditionally restores from that stack slot afterwards. A direct CSR write from C is silently overwritten the moment the handler resumes. This was found the hard way: an early version of trap_vec_check.c wrote mepc+4 via write_csr, and the core re-trapped on the same illegal instruction forever. See §5. 
trap_common:                       // sw/crt0.S
  addi sp, sp, -80
  <save ra, t0-t6, a0-a7>
  csrr t0, mepc   / sw t0, 64(sp)   // snapshot BEFORE calling C
  csrr t0, mstatus / sw t0, 68(sp)
  csrr a0, mcause  / csrr a1, mepc / csrr a2, mtval
  call trap_c_handler               // uint32_t trap_c_handler(mcause, mepc, mtval)
  sw   a0, 64(sp)                   // handler's return value IS the resume PC
  <restore mstatus, mepc from stack, then GPRs>
  mret

A weak default trap_c_handler (forward mcause to tohost, halt) covers any test that doesn't define its own — this is why hello_world.c needed zero changes when this infrastructure was added.

C↔SV irq mailbox

irq_ctrl is a linked symbol placed immediately after tohost in crt0.S's .data block, landing at 0x10004 — deterministic, the same trick that already pins tohost to 0x10000. ibex_driver.sv taps writes to that address and updates exactly one irq_* pin, leaving the others untouched.

BitsFieldMeaning
[31]assert1 = assert the line, 0 = deassert
[4:0]line_id0=software, 1=timer, 2=external, 3=nmi, 4..18=fast0..fast14

C side: irq_request(line_id, assert) in sw/common/irqmbox.h. Lines are level-sensitive and independent — asserting two before unmasking mstatus.MIE is exactly how the (planned) Phase 3 priority test works, no extra mechanism needed.

5 Bugs Found During Bring-up

Three real bugs surfaced while building this curriculum out — none were hypothetical, each was caught by an actual failing/hanging simulation run. Recorded here because the fix is part of the infrastructure every test now depends on.

SymptomRoot causeFix
All tests silently ran the wrong binary. Three different test programs reported TEST PASSED at identical simulation timestamps. tb_top.sv hardcoded $readmemh("sim/hello_world.vmem", mem_b) — invisible while only one test existed, since there was nothing else to load. Parameterized via $value$plusargs("VMEM_FILE=%s", ...); sim/Makefile now passes +VMEM_FILE=sim/$(TEST).vmem.
Illegal-instruction test looped forever re-trapping on the exact same PC every ~102 cycles, instead of resuming. trap_c_handler tried to change the resume PC via write_csr(mepc, mepc+4) directly. trap_common unconditionally restores mepc from a stack snapshot taken before the C call (required for nesting safety), silently discarding the CSR write. trap_c_handler now returns the desired resume PC; trap_common writes that return value into the stack slot before restoring from it. See §3.
Software and NMI interrupt tests hung at the 1 ms test timeout with no tohost write, while timer/external/fast0 (built the same way) passed. tb_top.sv's DUT instantiation tied .irq_software_i(1'b0) and .irq_nm_i(1'b0) to constants instead of connecting them to u_if.irq_software/u_if.irq_nm — harmless for years because nothing previously drove those interface signals dynamically. Both ports now wired to the interface signals, matching how irq_timer_i/irq_external_i/irq_fast_i were already connected.

6 Running / Adding a Test

cd sim
make sim TEST=<test_name>          # builds sw/tests/<test_name>.c + crt0.S, runs xrun
grep -E "PASSED|FAILED|UVM_ERROR|UVM_FATAL" runs/run_*/xrun.log | tail

To add a new test: drop a .c file in sw/tests/. Include sw/common/mmio.h for tohost/irq_ctrl, csr.h for CSR macros, irqmbox.h for irq_request(), and trap.h if defining a trap_c_handler. Write tohost=1 on success, a distinct small integer per failure mode otherwise (document what each code means in a comment — there's no shared fail-code registry, each test owns its own).
