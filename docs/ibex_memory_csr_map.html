1 System Memory Map

Modeled as one flat byte array mem_b[0:262143] in tb_top.sv (256 KB total). Zero-wait-state grant, 1-cycle registered rvalid/rdata on both instruction and data buses. There is no separate peripheral bus — ROM, RAM, and the UART alias all live in the same SRAM model.
ROM code / rodata — loaded from hello_world.vmem RAM data / bss / stack — read-write Alias mapped by convention only — no real HW behavior

2 ROM Layout Detail

Reset-vector dependency: Ibex always fetches its first post-reset instruction from {boot_addr_i[31:8], 8'h80} — fixed in hardware, independent of the linker script. That address previously held zeroed memory (an illegal instruction), which happened to trap to mtvec's reset value (0x0) — coinciding with the ROM origin by accident. sw/link.ld + sw/crt0.S now place a real _reset_entry trampoline at 0x80 explicitly, so the boot path no longer depends on that coincidence.
AddressSizeContents
0x0000_0000 – 0x0000_007F128 BReserved / unused — before the hardware reset vector
0x0000_00804 B_reset_entry — hardware boot fetch address. Single j _start trampoline.
0x0000_0084~72 B_start (crt0.S): install mtvec, set sp, zero .bss, call main, write tohost, halt loop
0x0000_00CC—trap_handler — direct-mode mtvec target for every exception/interrupt
0x0000_00xx – 0x0000_FFFF—Remaining .text/.rodata — main(), alu_add(), etc.
