ECC Fundamentals
Q8.1What is ECC? How does Hamming code detect and correct errors?MED▾
Answer
ECC (Error Correction Code): adds redundant parity bits to data. On read, recalculate parity bits and XOR with stored bits → syndrome. Syndrome=0: no error. Syndrome≠0: identifies error bit position (for single-bit errors).

Hamming code mechanics: parity bits placed at power-of-2 positions (1, 2, 4, 8...). Each parity bit covers specific data bit subsets. Parity1 covers positions 1,3,5,7... Parity2 covers positions 2,3,6,7... etc. Syndrome is the binary number formed by all parity check results — directly gives the error bit position.

SECDED (Single Error Correct, Double Error Detect): standard Hamming + one overall parity bit. If syndrome≠0 and overall parity changes → single-bit error (correctable). If syndrome≠0 and overall parity unchanged → double-bit error (detected, not correctable — report DERR flag).
💡 Insight
ECC is asked at Intel (ECC for memory subsystem), Tenstorrent, and Samsung. The key distinction to know: standard Hamming can detect and correct single-bit errors, and detect (but not correct) double-bit errors. SECDED adds one bit to distinguish between correctable (1-bit) and detected-only (2-bit) scenarios. Hardware ECC controllers assert separate SECDED and DERR status flags.
Q8.2How many ECC bits for different data widths? Formula.MED▾
Answer
Formula: find smallest p such that 2^p ≥ p + d + 1 (where d = data bits, p = parity bits, +1 for SECDED overall parity bit).

8-bit data: p = 4 ECC bits (total word = 12 bits)
16-bit data: p = 5 ECC bits (total word = 21 bits)
32-bit data: p = 6 ECC bits (total word = 38 bits)
64-bit data: p = 7 ECC bits (total word = 71 bits)
128-bit data: p = 8 ECC bits (total word = 136 bits)

Verify 32-bit: 2^6=64 ≥ 6+32+1=39. ✓ 2^5=32 ≥ 38? No. ✗ So p=6 is minimum.
💡 Insight
Verification implication: for 32-bit data with 6 ECC bits, you're storing 38 bits. The ECC encoder computes 6 parity bits on write, stores all 38 bits. On read: recomputes 6 parity bits, XORs with stored → 6-bit syndrome. Must test ALL 38 single-bit positions (inject each, verify correction). For double-bit: inject pairs, verify DERR flag (no correction). This is a systematic test matrix.
Q8.3Will ECC correct a 2-bit error? How does SECDED flag correctable vs uncorrectable?MED▾
Answer
Standard Hamming: can detect 2-bit errors but CANNOT correct them — syndrome indicates error but the bit position mapping is ambiguous for 2-bit errors.

SECDED behaviour:
Scenario 1 — Single-bit error: syndrome≠0 AND overall parity bit changes → position unambiguously identified → hardware corrects by flipping that bit → SECD flag asserted (correctable error logged).
Scenario 2 — Double-bit error: syndrome≠0 AND overall parity bit unchanged → indicates uncorrectable → hardware does NOT attempt correction → DERR flag asserted → system/OS notified for higher-level action (typically: mark page as bad, trigger NMI, log to firmware).
Scenario 3 — No error: syndrome=0, overall parity=0 → clean read, no flags.
💡 Insight
The DERR flag handling is important from a system perspective. When DERR is asserted, the hardware cannot know which 2 bits are wrong — correcting any bit would make it worse. The system must treat the data as unrecoverable. In server memory systems, DERR on a page triggers OS to mark it bad and remap. This is why DRAM SECDED ECC is not sufficient for critical data — RAID or redundant storage provides higher-level protection.
Q8.4How do you inject single-bit and multi-bit errors for ECC testing?MED▾
Answer
Single-bit error injection:
1. Write known data pattern to memory.
2. Read the stored word INCLUDING ECC bits via backdoor (or force the specific bit location in RTL).
3. Force exactly one bit to wrong value using HDL force/deposit or backdoor write to that bit position.
4. Read normally — ECC logic should detect, correct, and assert SECD flag.
5. Verify: corrected data matches original, SECD=1, DERR=0, error address logged correctly.

Double-bit error injection:
1. Write known pattern.
2. Force two specific bits simultaneously to wrong values.
3. Read — DERR=1, SECD=0, data returned is corrupted (do NOT use it).

Must test all bit positions: for 32-bit+6ECC=38 bits: inject error at each of 38 positions individually. Verify syndrome correctly identifies THAT position.
💡 Insight
The systematic test: for each bit position i in 0..37: write known pattern, force bit i, read back, verify syndrome=i+1, verify data correction, clear force, verify clean read. Then for double-bit: test all C(38,2)=703 combinations? No — sample a representative subset (same parity group, adjacent bits, MSB+LSB). Full coverage of all double-bit combinations is impractical — target statistically representative pairs and known-dangerous combinations.
Q8.5Cache hierarchy: L1, L2, L3. What is cache miss penalty?LOW▾
Answer
L1: smallest (32–64KB), fastest (1–4 cycles latency), private to each core, SRAM. Split into L1-I (instructions) and L1-D (data).
L2: larger (256KB–1MB), slower (5–12 cycles), may be private or shared, SRAM.
L3: largest (4–64MB+), slowest cache level (30–50 cycles), shared across all cores, SRAM but optimised for density over speed.
DRAM: hundreds of cycles latency (100–300 cycles), gigabytes, DDR4/DDR5.

Cache miss penalty: L1 miss → access L2 (5–8 cycle penalty). L2 miss → access L3 (30–40 cycle penalty). L3 miss → DRAM access (100–300 cycle penalty). This is why cache coherency and prefetching matter enormously for performance.
📌 Pro Tip
Cache hierarchy is asked at AMD and Tenstorrent (AI accelerators are highly cache-sensitive). The verification angle: cache controller verification — verify correct hit/miss behaviour, eviction policy (LRU, PLRU), write-back vs write-through, cache flush and invalidate operations, and coherency protocol state machine transitions.
