Protocol Questions
AXI asked in 8 of 10 interviews. Know all 5 channels, burst types, handshaking, out-of-order, and 4KB boundary cold.
⌕
AXI Protocol — HIGH frequency
Q4.1Name all 5 AXI channels and their key signals.HIGH▾
Answer
Write Address (AW): AWID, AWADDR, AWLEN, AWSIZE, AWBURST, AWVALID, AWREADY, AWLOCK, AWCACHE, AWPROT.

Write Data (W): WDATA, WSTRB, WLAST, WVALID, WREADY. [AXI3 also: WID]

Write Response (B): BID, BRESP, BVALID, BREADY.

Read Address (AR): ARID, ARADDR, ARLEN, ARSIZE, ARBURST, ARVALID, ARREADY, ARLOCK, ARCACHE, ARPROT.

Read Data (R): RID, RDATA, RRESP, RLAST, RVALID, RREADY.

BRESP/RRESP codes: OKAY(00), EXOKAY(01), SLVERR(10), DECERR(11).
💡 Insight
Memorise AWLEN, AWSIZE, AWBURST — these define burst behaviour. AWLEN+1 = number of beats. AWSIZE = bytes per beat (2^AWSIZE). AWBURST = FIXED/INCR/WRAP. WSTRB = byte enables (1 bit per byte lane) — tells slave which bytes are valid. WLAST = last beat — scoreboard must check this for correct burst termination detection. BRESP and RRESP: SLVERR means slave error (address exists but access failed). DECERR means address not mapped to any slave.
Q4.2Why separate write response channel? Why no separate read response?HIGH▾
Answer
Write response (B) is separate because: master needs to know all write data was successfully received and stored by the slave. This acknowledgement may come many cycles after WLAST — slave needs to fetch from cache, write to DRAM, etc. Decoupling it allows slave to process asynchronously. Without B channel, master must poll or stall, destroying bandwidth.

Read has no separate response because: read data (RDATA) and read status (RRESP) arrive together on the same channel. The slave cannot send data without also providing status. No need for a separate channel when data and status always travel together.
💡 Insight
This tests protocol architecture understanding beyond memorising signals. Follow-up at WD: 'What if BRESP is SLVERR — what does master do?' The master must treat the write as failed and retry or escalate to software. This is important for reliability in systems where write failures must be caught (e.g., register writes, DMA descriptor writes).
Q4.3Explain AXI handshake. What happens when VALID high but READY low?HIGH▾
Answer
AXI handshake rule: a transfer occurs when VALID and READY are BOTH high on the same clock edge. VALID driven by sender (master for AW/W, slave for B/R). READY driven by receiver.

When VALID high, READY low: sender must hold VALID and all associated signals stable until READY asserts. Sender CANNOT deassert VALID once asserted — this is a protocol requirement. Deasserting VALID before READY = protocol violation.

When READY high, VALID low: receiver is available, sender has nothing to send — receiver waits without stalling.

Either can assert first — no ordering requirement between VALID and READY.
💡 Insight
The 'VALID cannot be deasserted once asserted' rule is critical for verification. Write this assertion: @(posedge clk) AWVALID && !AWREADY |=> AWVALID. This ensures AWVALID stays high until AWREADY comes. Same for WVALID, ARVALID. AXI protocol violators that deassert VALID early cause very subtle, hard-to-find bugs in real silicon.
Q4.4What are AXI burst types? When is each used?HIGH▾
Answer
FIXED (AWBURST=00): same address for every beat. No address increment. Use case: peripheral FIFOs (always write/read from same FIFO data register address). All beats target identical address.

INCR (AWBURST=01): address increments by 2^AWSIZE bytes each beat. Most common. Use case: sequential memory access, DMA bulk transfer, cache line fill from DRAM.

WRAP (AWBURST=10): increments like INCR but wraps at a boundary. Wrap boundary = start of the transfer's natural alignment. Use case: cache line fill starting from required data — processor needs data at address 0x28, reads: 0x28, 0x30, 0x38, 0x00, 0x08... wraps to fill 64-byte cache line optimally.
💡 Insight
WRAP is the most misunderstood. The wrap boundary depends on: (number_of_beats × bytes_per_beat). For 8-beat, 8-byte transfer: boundary = 64 bytes. If start_addr=0x28: wrap at 0x40. Addresses: 0x28,0x30,0x38,0x40(wraps→0x00),0x08,0x10,0x18,0x20. This optimises cache fill latency — the requested data arrives first, cache line completes with the remaining surrounding data.
Q4.5AXI out-of-order transactions, data interleaving, and narrow transfers.HIGH▾
Answer
Out-of-order: slave can return read data or write responses in different order from requests. Each transaction has a unique ID (ARID/AWID). Master matches responses to requests via RID/BID. Enables higher throughput — fast slaves respond immediately while slow slaves catch up.

Data interleaving (AXI3 only): write data beats from different burst transactions can interleave on the W channel. WID identifies which transaction each beat belongs to. Removed in AXI4 — simplifies slave implementation significantly.

Narrow transfer: transfer size smaller than data bus width. 8-bit write on 32-bit bus. WSTRB indicates active byte lanes. Slave only updates bytes with corresponding WSTRB bit = 1. Other bytes unchanged.
💡 Insight
Out-of-order is what makes AXI high-performance. Without it: a slow DRAM access stalls all subsequent fast register accesses. With ID-based ordering: master fires multiple requests, collects responses as they complete. Scoreboard implication: use associative array keyed by ID for correct out-of-order comparison — queue-based scoreboard will produce false mismatches for out-of-order responses.
Q4.6AXI address calculation: INCR burst, start_addr=0x1000, AWLEN=7, AWSIZE=2.HIGH▾
Answer
AWLEN=7 → 8 beats (AWLEN+1). AWSIZE=2 → 4 bytes per beat (2^2=4).

Beat 0: 0x1000
Beat 1: 0x1004
Beat 2: 0x1008
Beat 3: 0x100C
Beat 4: 0x1010
Beat 5: 0x1014
Beat 6: 0x1018
Beat 7: 0x101C

Total transfer: 8 × 4 = 32 bytes (0x1000 to 0x101F).

4KB check: 0x1000 is in page 0x1000–0x1FFF. 0x101F also in same page. ✓ No boundary crossing.
💡 Insight
Formula: address_beat_N = start_addr + (N × 2^AWSIZE). The 4KB boundary check: start_addr[31:12] must equal end_addr[31:12] for all beats. If they differ → boundary crossing → AXI protocol violation. This calculation is tested at Insemi and Quest Global — know it without a calculator.
Q4.7AXI3 vs AXI4 key differences.HIGH▾
Answer
AXI4 improvements over AXI3:
1. Burst length: AWLEN/ARLEN 8-bit in AXI4 (max 256 beats for INCR) vs 4-bit AXI3 (max 16 beats).
2. No WID: write data interleaving removed. WID eliminated. All WDATA beats must belong to same burst in order.
3. AWREGION/ARREGION: 4-bit region field for address space extension.
4. AWQOS/ARQOS: Quality of Service signals for traffic prioritisation.
5. AXI4-Lite: simplified variant — no bursts, fixed 32/64-bit data, no AWID/ARID, designed for register access.
6. AXI4-Stream: data streaming — no address channel, continuous flow, TDATA/TVALID/TREADY/TLAST/TKEEP.
📌 Pro Tip
AXI4-Lite is the most common variant for CSR/register access in SoC — simpler than full AXI4, no burst overhead. AXI4-Stream is for video/audio data, network packets, ML tensor streaming. Knowing the variants and their appropriate use cases demonstrates real-world SoC architecture knowledge.
APB Protocol — HIGH frequency
Q4.8Explain APB protocol — all signals and both timing phases.HIGH▾
Answer
Signals: PCLK, PRESETn, PADDR, PSEL, PENABLE, PWRITE, PWDATA, PRDATA, PREADY, PSLVERR, PSTRB (APB4), PPROT (APB4).

Write timing:
Cycle 1 — SETUP phase: PSEL=1, PWRITE=1, PADDR=addr, PWDATA=data, PENABLE=0.
Cycle 2+ — ACCESS phase: PENABLE=1. Slave asserts PREADY when ready. Transfer completes when PREADY=1. PSLVERR indicates error.

Read timing: Same structure. PWRITE=0. Slave drives PRDATA valid when PREADY=1.

Wait states: Slave can hold PREADY=0 for multiple ACCESS cycles — allows slow peripherals. No maximum wait state count defined by spec.
⚠ Watch Out
Common APB mistake: asserting PSEL and PENABLE simultaneously (no SETUP phase) — this is a protocol violation. SETUP phase must last exactly 1 cycle. PENABLE only asserts on the second cycle (ACCESS phase). Monitor must check this timing.
Q4.9Write APB write and read driver tasks.HIGH▾
task apb_write(input [31:0] addr, data);
  // SETUP phase (1 cycle mandatory)
  @(posedge PCLK);
  PSEL    <= 1;
  PWRITE  <= 1;
  PADDR   <= addr;
  PWDATA  <= data;
  PENABLE <= 0;

  // ACCESS phase
  @(posedge PCLK);
  PENABLE <= 1;

  // Wait for slave ready (may insert wait states)
  @(posedge PCLK iff PREADY);

  // Check for error
  if(PSLVERR)
    `uvm_error("APB","Write error PSLVERR asserted");

  // Deassert
  PSEL    <= 0;
  PENABLE <= 0;
endtask

task apb_read(input [31:0] addr, output [31:0] rdata);
  @(posedge PCLK);
  PSEL    <= 1;
  PWRITE  <= 0;
  PADDR   <= addr;
  PENABLE <= 0;

  @(posedge PCLK);
  PENABLE <= 1;

  @(posedge PCLK iff PREADY);
  rdata = PRDATA;  // Capture on PREADY
  if(PSLVERR)
    `uvm_error("APB","Read error PSLVERR asserted");

  PSEL    <= 0;
  PENABLE <= 0;
endtask
💡 Insight
PREADY handling is the key complexity. Slave can assert PREADY=0 for any number of ACCESS phase cycles — slow peripherals like flash controllers or I2C bridges may need many cycles. The @(posedge PCLK iff PREADY) construct handles this correctly — waits any number of cycles until PREADY=1. Also check PSLVERR on completion — slave indicates error via this signal.
Q4.10Why use APB when AXI exists?HIGH▾
Answer
APB advantages: simpler interface (fewer signals, no burst, no out-of-order), lower power (no pipeline overhead, simpler clock domain, fewer state machines), lower area in slave implementation (especially for FPGA), sufficient bandwidth for slow peripherals (UART max ~1 Mbps, GPIO at register-access rates, timers, WDT, CSR registers).

AXI advantages: high bandwidth, pipelined transactions, multiple outstanding requests, out-of-order responses, byte-lane enables for narrow transfers.

Decision rule: use APB for anything that doesn't need high bandwidth and shouldn't stall the main bus. Typical SoC: AXI backbone → AXI-to-APB bridge → APB peripheral bus.
💡 Insight
This is a system architecture question. Understanding WHEN to use which protocol demonstrates SoC design experience beyond just protocol knowledge. The AXI-to-APB bridge is itself a common DV target — it must correctly convert AXI burst accesses to single APB transfers, handle write response aggregation, and manage the clock domain if APB runs slower.
AHB and Serial Protocols — MED frequency
Q4.11AHB vs AHB-Lite: differences and when to use each.MED▾
Answer
Full AHB adds over AHB-Lite: HMASTER (which master is active), HMASTLOCK (locked transfer), HBUSREQ/HGRANT (multi-master arbitration), HSPLIT (slave splits response — releases bus while processing), HREADY_IN vs HREADY_OUT (separate signals).

AHB-Lite removes: multi-master arbitration, SPLIT and RETRY responses. Only one master allowed. Much simpler slave implementation.

Use AHB-Lite: embedded processors with single master (ARM Cortex-M series uses AHB-Lite). Simpler, lower area.
Use AHB: multi-master systems needing arbitration. Mostly legacy — new designs prefer AXI.
💡 Insight
AHB-Lite is the real-world standard today — the majority of ARM Cortex-M-based SoCs use AHB-Lite. Full AHB with SPLIT transactions is complex and mostly found in legacy or high-performance legacy designs. AXI has replaced full AHB for new high-bandwidth designs. Knowing this history shows real industry awareness.
Q4.12AHB burst types and address boundary.MED▾
Answer
SINGLE: 1 transfer. INCR: incrementing, undefined length. INCR4/8/16: incrementing, exactly 4/8/16 beats. WRAP4/8/16: wrapping, exactly 4/8/16 beats — wraps at boundary.

AHB 1KB boundary rule: burst must not cross 1KB boundary (address bits [9:0] wrap). AXI uses 4KB boundary.

Pipelining: AHB is pipelined — address phase of beat N+1 overlaps with data phase of beat N. HREADY=0 stalls BOTH phases simultaneously.
💡 Insight
AHB 1KB vs AXI 4KB boundary is a specific trivia question at AMD (Onsemi). The reason AHB uses 1KB: AHB was designed for embedded systems where memory is segmented into smaller address-decoded regions. AXI's larger 4KB gives more flexibility for cache-line-sized bursts.
Q4.13UART, I2C, SPI — key differences.MED▾
Answer
UART: asynchronous (no clock), point-to-point, 2 wires (TX, RX). Start bit (LOW) signals start of frame. Both sides pre-agree on baud rate. Full duplex.

I2C: synchronous, multi-master/multi-slave, 2 wires (SDA, SCL). Address-based slave selection. SDA changes only when SCL=LOW (data phase). START = SDA falls while SCL=HIGH. STOP = SDA rises while SCL=HIGH.

SPI: synchronous, 4 wires (MOSI, MISO, SCLK, CS). Fastest of the three. CS (chip select) selects slave — no addressing. Full duplex. No ACK mechanism.
📌 Pro Tip
Common interview question at Samsung and WD: 'How does UART receiver know the start bit?' Answer: idle line is HIGH. Receiver detects falling edge as start bit. Then samples at baud-rate intervals from mid-start-bit to capture each data bit. UART is the simplest serial protocol but requires precise baud-rate matching — mismatch causes framing errors.
