JTAG Fundamentals
Q9.1Explain JTAG — what it is, pins, and use cases.MED▾
Answer
IEEE 1149.1 standard providing a standardised serial interface for testing, debugging, and programming chips and PCBs.

Pins:
TCK (Test Clock): clock signal for all JTAG operations — typically 1–100 MHz.
TMS (Test Mode Select): navigates the TAP controller FSM — controls which state to enter.
TDI (Test Data In): serial data input — shifts data into registers.
TDO (Test Data Out): serial data output — shifts data out from registers.
TRST_n (optional): asynchronous reset of TAP controller to Test-Logic-Reset state.

Use cases: (1) Pre-silicon: verify TAP controller FSM, boundary scan register, debug module register access. (2) Post-manufacture PCB test: boundary scan — verify PCB connectivity without physical probes. (3) In-field debug: halt processor, inspect registers, step through code, read/write memory. (4) Firmware programming: write to flash via JTAG interface.
💡 Insight
JTAG's value is that it provides debug access independent of the chip's normal operation. Even if the processor is hung in an infinite loop or dead after a firmware crash, JTAG can access the debug module to halt execution, dump register state, and inspect memory. This is why JTAG verification is safety-critical — a broken JTAG interface means zero debug capability in field, making post-silicon bringup extremely difficult.
Q9.2Explain TAP controller FSM. How do you navigate it? How do you reset from any state?MED▾
Answer
The TAP controller has 16 states controlled entirely by TMS (sampled on rising TCK edge).

Main states:
Test-Logic-Reset → Run-Test/Idle → Select-DR-Scan → Capture-DR → Shift-DR → Exit1-DR → Pause-DR → Exit2-DR → Update-DR
(Parallel IR path: Select-IR-Scan → Capture-IR → Shift-IR → Exit1-IR → Pause-IR → Exit2-IR → Update-IR)

Navigation: TMS=1 moves toward reset or toward Select. TMS=0 progresses through the data/IR path.
To reach Shift-DR from Idle: TMS=1,1,0,0 (Select-DR, Capture-DR, Shift-DR — 4 TCK cycles).
To reach Shift-IR from Idle: TMS=1,1,1,0,0 (5 TCK cycles).

Universal reset: drive TMS=1 for 5 consecutive TCK cycles — this ALWAYS returns to Test-Logic-Reset regardless of current state. The FSM is designed so any state with TMS=1 for 5 cycles reaches TLR.
💡 Insight
The 5×TMS=1 reset rule is important for error recovery and test start. In your UVM driver, implement reset_tap() task that drives TMS=1 for 5 cycles at the beginning of every test — guarantees known starting state. In hardware, this is also how JTAG dongles reset the TAP before programming — they don't know the current state, so they force TLR first.
Q9.3How do you read a register via JTAG? Walk through TMS/TDI sequence step by step.MED▾
Answer
Step-by-step to read a JTAG data register:

Step 1 — Load instruction (select target register):
Navigate to Shift-IR: TMS=1,1,1,0,0 from Idle.
Shift instruction opcode (e.g., IDCODE=0001) via TDI, LSB first, over TCK cycles.
Navigate to Update-IR: TMS=1,1. Instruction loaded — target DR selected.

Step 2 — Access the data register:
Navigate to Shift-DR: TMS=1,0,0 from Update-IR.
Clock TCK — in Capture-DR (one state before Shift-DR) the register content is captured into the shift register.
Shift out via TDO: clock TCK cycles equal to register width — data shifts out MSB or LSB (implementation-defined).

Step 3 — Return to idle:
TMS=1,1,0 → Update-DR → Idle.

For write: shift new data via TDI in Shift-DR, then Update-DR latches it.
💡 Insight
The exact TMS sequence is asked at WD (Sivason). WD specifically asked: 'How do you decode TDI input of address+data+opcode?' The answer: for a complex debug register (like RISC-V DMI — Debug Module Interface), the 41-bit TDI field contains: address[6:0] + data[31:0] + op[1:0]. Split the 41 TDI bits on each TCK edge, extract fields, and verify the correct debug module register is being accessed with the correct value.
Q9.4What are boundary scan cells? How do you use them to test PCB connectivity?MED▾
Answer
Boundary scan cells: shift register flip-flops added to each I/O pin of a chip during design. Connected in series, forming the Boundary Scan Register (BSR). The entire BSR forms one long shift register accessible via JTAG TDI/TDO.

Three operating modes:
Capture: BSR cells capture the current state of all I/O pins (what pins are actually driven).
Shift: data shifts through all BSR cells serially (via TDI to TDO).
Update: new data from BSR shifts is driven onto the output pins (overrides normal chip function).

PCB connectivity test: (1) Drive known pattern onto chip A's output pins via Update mode. (2) Capture the values seen at chip B's input pins. (3) Compare: if PCB connection is good, B sees exactly what A drove. Pin-to-pin continuity verified without physical probes or oscilloscope.
💡 Insight
Boundary scan enables post-manufacture test of PCB connectivity at scale. Before JTAG, every pin had to be physically probed — extremely slow for dense BGAs. With JTAG boundary scan: one test program vectors all output pins in seconds. This is why virtually all production chips include JTAG even if not needed for debug — it's essential for manufacturing test.
Q9.5What is UVM testbench architecture for JTAG? How is communication established between C and UVM?MED▾
Answer
UVM TB architecture for JTAG:
JTAG agent (active): driver + sequencer + monitor connected to TCK, TMS, TDI, TDO pins.
Driver: implements TAP state machine navigation, shifts TDI data at correct TCK rate.
Monitor: samples TDO on each TCK rising edge, reconstructs register reads.
Sequence library: jtag_reset_seq, jtag_write_seq, jtag_read_seq, jtag_idcode_seq.

C to UVM communication:
In SoC verification with JTAG: the C program can initiate JTAG operations via memory-mapped JTAG controller registers (if the SoC has one). UVM monitors the JTAG pins passively. Alternatively, C writes to a 'mailbox' (dedicated scratch registers) — UVM driver reads the mailbox and translates to JTAG TDI/TMS sequences. DPI: C function directly calls SV task to initiate specific JTAG operations.
💡 Insight
JTAG TB is complex because you need to: (1) implement the 16-state TAP FSM in the driver — not trivial. (2) handle variable-width data register shifts (IDCODE=32 bits, DMI=41 bits, custom registers vary). (3) synchronise between the slow JTAG clock (TCK) and the fast system clock for meaningful tests. The monitor must correctly reconstruct multi-bit reads from serial TDO bits shifted over multiple TCK cycles.
