01

Why UVM exists — and what it solves

Module 1 · ~4 min · Hook
Outcome: Understand what problem UVM solves, why ad-hoc testbenches fail at scale, and what the three pillars of UVM give you that SystemVerilog alone cannot.

Your SV testbench works fine for a single block. Then the project grows: 4 engineers, 12 IP blocks, 3 different interface protocols, and a top-level integration test that nobody owns. Stimulus gets duplicated. Scoreboards drift out of sync. Coverage models conflict. Six months before tapeout, you discover nobody was checking the same thing.

UVM (IEEE 1800.2) is the industry standard answer. It provides a class-based, reusable framework with a defined component hierarchy, a phased execution model, and a standard factory that lets you swap components without rewriting the testbench.

The three pillars UVM gives you
Pillar 1
Reusability
Every component is a parameterised class. A driver written for one DUT port can be extended, not rewritten, for a new project. The factory enables override without code changes.
Pillar 2
Structured phasing
UVM defines 12 standard phases (build → connect → run → check → report). Every component participates. No more race conditions between testbench setup and simulation start.
Pillar 3
Separation of concerns
Stimulus (sequence), driving (driver), checking (scoreboard), and configuration (config object) are separate classes. Each engineer owns one layer. Integration is the framework's job.

Test
uvm_test — controls which sequences run, configures the environment

Key takeaway: UVM solves the scalability problem of ad-hoc SV testbenches. Every component has a defined role. The phased execution model eliminates race conditions. The factory enables swapping components without editing code.
02

Testbench hierarchy and UVM factory

Module 2 · ~6 min · Core architecture
Outcome: Build the skeleton of a UVM testbench — top module, interface, component registration, factory overrides, and the two-line test launch that wires it all together.
The testbench top module — static SV, not a class
The tb_top module is the only non-class piece of your testbench. It instantiates the DUT, creates the interface, and passes the virtual interface into the UVM config DB. Everything else is class-based and runs under run_test().
tb_top.sv
module tb_top;
  import uvm_pkg::*;
  `include "uvm_macros.svh"
  `include "my_pkg.sv"   // your testbench package

  // Clock and reset generation
  bit clk;
  always #5 clk = ~clk;

  // Interface instantiation
  my_if dut_if (.clk(clk));

  // DUT instantiation
  my_dut dut (.clk(clk), .a(dut_if.a), .b(dut_if.b), .out(dut_if.out));

  // Pass vif into config DB — UVM components retrieve it from here
  initial begin
    uvm_config_db#(virtual my_if)::set(null, "uvm_test_top.*", "vif", dut_if);
    run_test();  // launches the test class named on +UVM_TESTNAME=
  end
endmodule
UVM factory — registration and override

Every UVM component and object must be registered with the factory using macros. Registration is what allows the factory override mechanism to swap one implementation for another without changing any other code.

factory registration macros
// For uvm_component subclasses (driver, monitor, agent, env, test)
`uvm_component_utils(my_driver)

// For uvm_object subclasses (sequence_item, sequence, config objects)
`uvm_object_utils(my_seq_item)

// With field macros — enables print/copy/compare/pack automatically
`uvm_object_utils_begin(my_seq_item)
  `uvm_field_int(addr,  UVM_ALL_ON)
  `uvm_field_int(data,  UVM_ALL_ON)
  `uvm_field_int(write, UVM_ALL_ON)
`uvm_object_utils_end

// Factory override — swap my_driver with error_driver for one test
// Put this in the test's build_phase before super.build_phase()
my_driver::type_id::set_type_override(error_driver::get_type());
Component creation — always use the factory
create via factory, not new()
// WRONG — bypasses factory, override will never apply
my_driver drv = new("drv", this);

// CORRECT — always use type_id::create()
my_driver drv = my_driver::type_id::create("drv", this);

// For objects (sequences, sequence items) — no parent argument
my_seq_item item = my_seq_item::type_id::create("item");
Logging — UVM reporting macros
reporting
`uvm_info   (get_type_name(), "Driving transaction", UVM_MEDIUM)
`uvm_warning(get_type_name(), "Unexpected X on bus")
`uvm_error  (get_type_name(), "Scoreboard mismatch!")
`uvm_fatal  (get_type_name(), "Interface not found in config DB")

// Verbosity levels: UVM_NONE UVM_LOW UVM_MEDIUM UVM_HIGH UVM_FULL UVM_DEBUG
// Simulator flag: +UVM_VERBOSITY=UVM_HIGH
Key takeaway: tb_top is static SV — it creates the interface and calls run_test(). Everything inside is class-based. Always use type_id::create(), never new() — that's what makes factory overrides work.
03

Sequence Item — the transaction object

Module 3 · ~7 min · Core concept
Outcome: Write a complete sequence item with utility macros, field macros, randomisation constraints, and all built-in methods — print, copy, clone, compare, pack, unpack.
What is a sequence item?

A uvm_sequence_item is the transaction — the unit of stimulus. It represents one bus transfer, one packet, one register access. The driver converts it into pin-level wiggling. The scoreboard uses it to check the DUT's response.

Think of it as a struct with superpowers: built-in randomisation, automatic print/compare/pack methods, deep-copy support, and factory registration — all from macros.

complete sequence item — APB transaction
class apb_seq_item extends uvm_sequence_item;
  // ── factory registration ─────────────────────────────────────
  `uvm_object_utils_begin(apb_seq_item)
    `uvm_field_int(addr,  UVM_ALL_ON)
    `uvm_field_int(data,  UVM_ALL_ON)
    `uvm_field_int(write, UVM_ALL_ON | UVM_BIN)
    `uvm_field_int(prot,  UVM_ALL_ON | UVM_NOCOMPARE)
  `uvm_object_utils_end

  // ── fields ───────────────────────────────────────────────────
  rand logic [31:0] addr;
  rand logic [31:0] data;
  rand logic        write;   // 1=write, 0=read
  rand logic [2:0]  prot;

  // ── constraints ──────────────────────────────────────────────
  constraint c_addr_align { addr[1:0] == 2'b00; }  // word-aligned
  constraint c_addr_range { addr inside {[32'h4000_0000 : 32'h4000_FFFF]}; }
  constraint c_write_dist { write dist { 1 := 70, 0 := 30 }; }

  // ── constructor ──────────────────────────────────────────────
  function new(string name = "apb_seq_item");
    super.new(name);
  endfunction

  // ── custom display ───────────────────────────────────────────
  function string convert2string();
    return $sformatf("[%s] ADDR=%0h DATA=%0h WRITE=%0b",
                     get_name(), addr, data, write);
  endfunction
endclass
Field macro flags — controlling built-in behaviour
FlagEffect
UVM_ALL_ONEnables copy, compare, print, pack, record for this field
UVM_NOCOPYExclude from copy/clone
UVM_NOCOMPAREExclude from compare (e.g. timestamp, protocol signals)
UVM_NOPRINTExclude from print/sprint
UVM_NOPACKExclude from pack/unpack
UVM_BIN / UVM_HEX / UVM_DECPrint radix for this field
Built-in methods — what the macros give you for free
built-in object methods
apb_seq_item item, item2, item3;
item = apb_seq_item::type_id::create("item");

// print — displays all UVM_ALL_ON fields to log
item.print();

// copy — shallow copy (fields) from item into item2 (item2 must exist)
item2 = apb_seq_item::type_id::create("item2");
item2.copy(item);

// clone — creates a new object + copies (deep copy)
$cast(item3, item.clone());

// compare — returns 1 if equal, 0 if different (uses uvm_comparer)
if (!item.compare(item2))
  `uvm_error("SCB", "Transaction mismatch!")

// pack_bytes — serialise fields into byte array (for coverage, TLM)
byte packed[];
item.pack_bytes(packed);

// unpack_bytes — deserialise back into a new item
item2.unpack_bytes(packed);

  3. Write the constructor calling super.new(name).
  4. Override convert2string() to print addr and data in hex.
Reference answer
axil_seq_item.sv
class axil_seq_item extends uvm_sequence_item;
  `uvm_object_utils_begin(axil_seq_item)
    `uvm_field_int(awaddr,     UVM_ALL_ON | UVM_HEX)
    `uvm_field_int(awprot,     UVM_ALL_ON | UVM_BIN)
    `uvm_field_int(wdata,      UVM_ALL_ON | UVM_HEX)
    `uvm_field_int(wstrb,      UVM_ALL_ON | UVM_HEX)
    `uvm_field_int(write_flag, UVM_ALL_ON | UVM_BIN)
  `uvm_object_utils_end

  rand logic [31:0] awaddr;
  rand logic [2:0]  awprot;
  rand logic [31:0] wdata;
  rand logic [3:0]  wstrb;
  rand bit          write_flag;

  constraint c_align  { awaddr[1:0] == 2'b00; }
  constraint c_wstrb  { write_flag -> (wstrb != 4'h0); }

  function new(string name = "axil_seq_item");
    super.new(name);
  endfunction

  function string convert2string();
    return $sformatf("AWADDR=%0h WDATA=%0h WSTRB=%0h W=%0b",
                     awaddr, wdata, wstrb, write_flag);
  endfunction
endclass
Key takeaway: The sequence item is your transaction DNA. Field macros give you print/copy/compare/pack for free. UVM_NOCOMPARE excludes protocol-only fields from scoreboard checking. Always override convert2string() — your debug logs will thank you.

UVM Phases and Config DB

Module 4 · ~8 min · Core concept
Outcome: Use all 12 UVM phases correctly, never misplace logic between build and run, and pass configuration objects and virtual interfaces through the hierarchy using config DB.
The 12 UVM phases — what runs and when
PhaseTypeWhat you do here
build_phasefunctionCreate child components with type_id::create(). Set config DB values for children.
connect_phasefunctionConnect TLM ports. Get virtual interfaces from config DB.
end_of_elaboration_phasefunctionPrint topology, final checks before simulation.
start_of_simulation_phasefunctionPrint configuration, set initial state.
run_phasetaskMain simulation — drive stimulus, monitor, score. Uses phase.raise_objection().
extract_phasefunctionCollect results from scoreboards/monitors.
check_phasefunctionFinal pass/fail checks — scoreboards report here.
report_phasefunctionPrint summary statistics and coverage.
final_phasefunctionLast chance cleanup before simulator exits.
phase skeleton — build + connect + run
class my_env extends uvm_env;
  `uvm_component_utils(my_env)

  my_agent    m_agent;
  my_scoreboard m_scb;

  function void build_phase(uvm_phase phase);
    super.build_phase(phase);
    // Create components — order matters (parent before child)
    m_agent = my_agent::type_id::create("m_agent", this);
    m_scb   = my_scoreboard::type_id::create("m_scb", this);
  endfunction

  function void connect_phase(uvm_phase phase);
    // Connect monitor's analysis port to scoreboard's export
    m_agent.m_monitor.ap.connect(m_scb.analysis_export);
  endfunction
endclass
Objection mechanism — controlling simulation end
Critical: The run_phase ends when all objections are dropped. If you never raise an objection, simulation ends immediately at time 0. Always raise in the test's run_phase, lower when done.
objection pattern
task run_phase(uvm_phase phase);
  my_sequence seq;
  phase.raise_objection(this);         // sim runs while objection held
  seq = my_sequence::type_id::create("seq");
  seq.start(m_env.m_agent.m_sequencer);
  // optional: add drain time for last transaction to complete
  #100ns;
  phase.drop_objection(this);          // sim ends when all drop
endtask
Config DB — passing interfaces and config objects

The config DB is UVM's global key-value store. It decouples the testbench top (static) from the class-based components. The interface goes in at tb_top, comes out in connect_phase of the driver/monitor.

config DB set (tb_top) and get (driver/monitor)
// ── SET in tb_top initial block ───────────────────────────────
uvm_config_db#(virtual my_if)::set(
  null,                // context (null = global)
  "uvm_test_top.*",    // scope path — wildcard matches all children
  "vif",               // key name
  dut_if               // value
);

// ── GET in driver or monitor connect_phase ───────────────────
virtual my_if vif;
function void connect_phase(uvm_phase phase);
  if (!uvm_config_db#(virtual my_if)::get(this, "", "vif", vif))
    `uvm_fatal("NOVIF", "Virtual interface not found in config DB!")
endfunction

// ── Passing config objects (e.g. APB config) ─────────────────
apb_config cfg = apb_config::type_id::create("cfg");
cfg.base_addr   = 32'h4000_0000;
cfg.is_active   = UVM_ACTIVE;
uvm_config_db#(apb_config)::set(this, "m_agent*", "cfg", cfg);
Key takeaway: Build phase creates. Connect phase wires. Run phase drives. Always raise the objection before stimulus starts and drop it when done. Config DB is the standard handshake for passing virtual interfaces from static SV into the class-based testbench hierarchy.

Sequences and Sequencer

Module 5 · ~8 min · Core component
Outcome: Write single, nested, and virtual sequences. Control the sequencer arbitration. Use sequence macros and start_item/finish_item correctly.
The sequence — ordered stimulus pipeline

A sequence is a class that generates a stream of sequence items. It has no clock — it is purely transactional. The sequencer queues items and the driver pulls them one at a time using the get_next_item / item_done handshake.

basic sequence — write burst
class apb_write_seq extends uvm_sequence#(apb_seq_item);
  `uvm_object_utils(apb_write_seq)

  int num_txns = 8;  // configurable from test

  function new(string name = "apb_write_seq");
    super.new(name);
  endfunction

  task body();
    apb_seq_item item;
    repeat(num_txns) begin
      item = apb_seq_item::type_id::create("item");
      start_item(item);             // request sequencer slot
      if (!item.randomize() with { write == 1; })
        `uvm_fatal("RAND", "Randomization failed")
      finish_item(item);            // send to driver, wait for ack
    end
  endtask
endclass
Sequence macros — shorthand for start_item/finish_item
`uvm_do family macros
// `uvm_do — create, randomize, start, finish in one line
`uvm_do(item)

// `uvm_do_with — randomize with inline constraints
`uvm_do_with(item, { item.write == 1; item.addr == 32'h1000; })

// `uvm_do_on — start item on a specific sequencer
`uvm_do_on(item, p_sequencer)

// `uvm_create + `uvm_rand_send — separate create from send
`uvm_create(item)
item.addr = 32'hDEAD;  // direct assignment
`uvm_rand_send_with(item, { item.write == 0; })
Nested and virtual sequences
nested sequences and virtual sequence
// Nested sequence — calls sub-sequences in order
class apb_init_seq extends uvm_sequence#(apb_seq_item);
  `uvm_object_utils(apb_init_seq)
  task body();
    apb_write_seq  wr_seq;
    apb_read_seq   rd_seq;
    `uvm_do(wr_seq)  // write phase
    `uvm_do(rd_seq)  // then read phase
  endtask
endclass

// Virtual sequence — controls multiple sequencers simultaneously
class top_virtual_seq extends uvm_sequence;
  `uvm_object_utils(top_virtual_seq)
  // handles to all sequencers — set by test before start()
  apb_sequencer  apb_seqr;
  axi_sequencer  axi_seqr;
  task body();
    apb_write_seq  apb_seq;
    axi_read_seq   axi_seq;
    fork
      apb_seq.start(apb_seqr);   // runs in parallel
      axi_seq.start(axi_seqr);
    join
  endtask
endclass
The sequencer — arbitration and flow control
sequencer declaration and arbitration
// Sequencer declaration (usually just typedef)
typedef uvm_sequencer#(apb_seq_item) apb_sequencer;

// Sequencer arbitration modes (set in build_phase)
m_sequencer.set_arbitration(UVM_SEQ_ARB_FIFO);      // default, in-order
m_sequencer.set_arbitration(UVM_SEQ_ARB_RANDOM);    // random pick
m_sequencer.set_arbitration(UVM_SEQ_ARB_WEIGHTED);  // by priority
m_sequencer.set_arbitration(UVM_SEQ_ARB_STRICT_FIFO); // strict priority

// Sequence control — locking the sequencer
seq.grab(m_sequencer);     // exclusive access, blocks other sequences
// ... send high-priority stimulus ...
seq.ungrab(m_sequencer);   // release
Key takeaway: Sequences are pure stimulus logic — no clocks, no DUT knowledge. Use start_item/finish_item for explicit control, `uvm_do_with for inline constraints. Virtual sequences coordinate multiple agents in parallel using fork/join.

UVM Driver — pin-level stimulus

Module 6 · ~7 min · Core component
Outcome: Write a complete driver that gets items from the sequencer, drives them onto the virtual interface cycle-accurately, and handles reset cleanly.
Driver anatomy

The driver bridges the transactional world (sequence items) and the pin-level world (virtual interface). It runs in run_phase, loops forever pulling items from the sequencer with seq_item_port.get_next_item(), drives them cycle-by-cycle, then calls item_done() to signal completion.

complete APB driver
class apb_driver extends uvm_driver#(apb_seq_item);
  `uvm_component_utils(apb_driver)

  virtual apb_if vif;

  function new(string name, uvm_component parent);
    super.new(name, parent);
  endfunction

  function void connect_phase(uvm_phase phase);
    if(!uvm_config_db#(virtual apb_if)::get(this,"","vif",vif))
      `uvm_fatal("NOVIF","No virtual interface")
  endfunction

  task run_phase(uvm_phase phase);
    apb_seq_item req;
    // Wait for reset to deassert before driving
    @(posedge vif.PRESETn);
    forever begin
      seq_item_port.get_next_item(req);  // blocking get from sequencer
      drive_item(req);                   // pin-level driving
      seq_item_port.item_done();         // unblock sequencer
    end
  endtask

  task drive_item(apb_seq_item req);
    // Setup phase: assert PSEL, deassert PENABLE
    @(posedge vif.PCLK);
    vif.PSEL    <= 1;
    vif.PENABLE <= 0;
    vif.PWRITE  <= req.write;
    vif.PADDR   <= req.addr;
    vif.PWDATA  <= req.data;
    // Access phase: assert PENABLE
    @(posedge vif.PCLK);
    vif.PENABLE <= 1;
    // Wait for PREADY — slave may insert wait states
    do @(posedge vif.PCLK); while(!vif.PREADY);
    // End of transfer: deassert PSEL and PENABLE
    vif.PSEL    <= 0;
    vif.PENABLE <= 0;
    `uvm_info(get_type_name(), req.convert2string(), UVM_HIGH)
  endtask
endclass
Pattern: Use try_next_item() instead of get_next_item() when you need to idle the bus during gaps in the sequence stream. try_next_item returns null if no item is available, allowing you to drive idle cycles.
try_next_item pattern for bus idle
task run_phase(uvm_phase phase);
  apb_seq_item req;
  forever begin
    seq_item_port.try_next_item(req);
    if (req != null) begin
      drive_item(req);
      seq_item_port.item_done();
    end else begin
      drive_idle();     // drive bus to idle state for one cycle
      @(posedge vif.PCLK);
    end
  end
endtask
Key takeaway: Driver = get_next_item → drive_item → item_done, forever. Get the virtual interface in connect_phase, not build_phase. Wait for reset before driving. Use try_next_item when you need to drive idle states between transactions.
07

Monitor and Scoreboard

Module 7 · ~8 min · Core components
Outcome: Write a monitor that samples DUT outputs and broadcasts via TLM analysis port, and a scoreboard that receives from both the reference model and monitor, compares, and reports.
Monitor — passive observer, never drives

The monitor samples the DUT interface at clock edges and converts signal-level activity into sequence items. It then writes each captured item into an analysis port — a broadcast mechanism that any number of subscribers (scoreboards, coverage collectors) can connect to.

APB monitor
class apb_monitor extends uvm_monitor;
  `uvm_component_utils(apb_monitor)

  virtual apb_if                          vif;
  uvm_analysis_port#(apb_seq_item)        ap;  // broadcast port

  function new(string name, uvm_component parent);
    super.new(name, parent);
  endfunction

  function void build_phase(uvm_phase phase);
    ap = new("ap", this);  // analysis port — created in build
  endfunction

  function void connect_phase(uvm_phase phase);
    if(!uvm_config_db#(virtual apb_if)::get(this,"","vif",vif))
      `uvm_fatal("NOVIF","No virtual interface")
  endfunction

  task run_phase(uvm_phase phase);
    apb_seq_item item;
    forever begin
      // Wait for a completed transfer (PSEL + PENABLE + PREADY)
      @(posedge vif.PCLK);
      if(vif.PSEL && vif.PENABLE && vif.PREADY) begin
        item = apb_seq_item::type_id::create("item");
        item.addr  = vif.PADDR;
        item.data  = vif.PWRITE ? vif.PWDATA : vif.PRDATA;
        item.write = vif.PWRITE;
        ap.write(item);  // broadcast to all connected subscribers
      end
    end
  endtask
endclass
Scoreboard — the checker
scoreboard with reference model
class apb_scoreboard extends uvm_scoreboard;
  `uvm_component_utils(apb_scoreboard)

  // Two analysis exports — one from monitor, one from ref model
  uvm_analysis_export#(apb_seq_item) mon_export;
  uvm_analysis_export#(apb_seq_item) ref_export;

  uvm_tlm_analysis_fifo#(apb_seq_item) mon_fifo;
  uvm_tlm_analysis_fifo#(apb_seq_item) ref_fifo;

  int pass_count, fail_count;

  function void build_phase(uvm_phase phase);
    mon_export = new("mon_export", this);
    ref_export = new("ref_export", this);
    mon_fifo   = new("mon_fifo", this);
    ref_fifo   = new("ref_fifo", this);
  endfunction

  function void connect_phase(uvm_phase phase);
    mon_export.connect(mon_fifo.analysis_export);
    ref_export.connect(ref_fifo.analysis_export);
  endfunction

  task run_phase(uvm_phase phase);
    apb_seq_item mon_item, ref_item;
    forever begin
      mon_fifo.get(mon_item);   // blocking: wait for monitor item
      ref_fifo.get(ref_item);   // blocking: wait for reference item
      if (!mon_item.compare(ref_item)) begin
        `uvm_error("SCB", $sformatf("MISMATCH\n  GOT: %s\n  EXP: %s",
                   mon_item.convert2string(), ref_item.convert2string()))
        fail_count++;
      end else pass_count++;
    end
  endtask

  function void report_phase(uvm_phase phase);
    `uvm_info("SCB",$sformatf("RESULTS: PASS=%0d FAIL=%0d",
              pass_count,fail_count),UVM_NONE)
  endfunction
endclass
Key takeaway: The monitor is passive — it only reads the interface, never drives it. The analysis port is a broadcast bus — one ap.write() call reaches every connected export. Scoreboards use FIFOs to buffer items from both monitor and reference model and compare them in the run_phase.
08

Agent and Environment

Module 8 · ~7 min · Integration layer
Outcome: Assemble the agent (sequencer + driver + monitor) and environment (agents + scoreboard), wire TLM connections, and configure active vs passive mode.
The agent — reusable verification IP

The agent is the reusable unit you'd package as a VIP. An active agent contains all three sub-components (sequencer + driver + monitor). A passive agent contains only the monitor — used when you're observing a bus that another master drives.

APB agent — active/passive configurable
class apb_agent extends uvm_agent;
  `uvm_component_utils(apb_agent)

  apb_driver     m_driver;
  apb_monitor    m_monitor;
  apb_sequencer  m_sequencer;

  uvm_active_passive_enum is_active = UVM_ACTIVE;  // default: active

  function void build_phase(uvm_phase phase);
    super.build_phase(phase);
    // Get is_active from config DB if set by test
    uvm_config_db#(uvm_active_passive_enum)::get(
      this, "", "is_active", is_active);
    // Monitor always created — even passive agents need to observe
    m_monitor = apb_monitor::type_id::create("m_monitor", this);
    if(is_active == UVM_ACTIVE) begin
      m_driver    = apb_driver::type_id::create("m_driver", this);
      m_sequencer = apb_sequencer::type_id::create("m_sequencer", this);
    end
  endfunction

  function void connect_phase(uvm_phase phase);
    if(is_active == UVM_ACTIVE)
      m_driver.seq_item_port.connect(m_sequencer.seq_item_export);
  endfunction
endclass

TLM — Transaction Level Modelling ports

Module 10 · ~8 min · Advanced
Outcome: Connect components using TLM ports, exports, and FIFOs. Understand blocking vs non-blocking transport, analysis ports, and when to use each.
TLM port types — the connection fabric
Analysis
uvm_analysis_port
One-to-many broadcast. write() call. No blocking. Used by monitors to fan out to scoreboards, coverage, loggers simultaneously.
Blocking get
uvm_get_port
Consumer pulls from producer. Blocks until item available. Driver ← Sequencer uses seq_item_port which is a specialised get port.
Blocking put
uvm_put_port
Producer pushes to consumer. Blocks until consumer accepts. Alternative to analysis for point-to-point non-broadcast transfer.
FIFO
uvm_tlm_analysis_fifo
Decouples producer and consumer timing. Analysis port writes into FIFO; consumer reads with get(). Standard scoreboard pattern.
TLM connection patterns
// ── Analysis: one monitor → two subscribers ───────────────────
// In build_phase of each component:
uvm_analysis_port#(apb_seq_item)   mon.ap;        // producer
uvm_analysis_export#(apb_seq_item) scb.mon_export; // consumer 1
uvm_analysis_export#(apb_seq_item) cov.ap_export;  // consumer 2
// In connect_phase (env level):
mon.ap.connect(scb.mon_export);
mon.ap.connect(cov.ap_export);   // analysis supports fan-out

// ── Analysis FIFO — decouple timing between monitor and scoreboard
uvm_tlm_analysis_fifo#(apb_seq_item) fifo;
// Connect monitor → FIFO input
mon.ap.connect(fifo.analysis_export);
// Scoreboard reads from FIFO (blocking get)
fifo.get(item);  // blocks until item available

// ── Blocking transport — point-to-point with response ─────────
uvm_blocking_transport_port#(req_t,rsp_t) port;
uvm_blocking_transport_imp#(req_t,rsp_t,component) imp;
// Usage:
port.transport(req, rsp);  // sends req, blocks, gets rsp back
TLM FIFO — the scoreboard buffer pattern in full
analysis FIFO usage in scoreboard
class apb_scoreboard extends uvm_scoreboard;
  `uvm_component_utils(apb_scoreboard)

  uvm_tlm_analysis_fifo#(apb_seq_item) exp_fifo; // expected (ref model)
  uvm_tlm_analysis_fifo#(apb_seq_item) act_fifo; // actual (DUT monitor)

  function void build_phase(uvm_phase phase);
    exp_fifo = new("exp_fifo", this);
    act_fifo = new("act_fifo", this);
  endfunction

  task run_phase(uvm_phase phase);
    apb_seq_item exp_item, act_item;
    forever begin
      exp_fifo.get(exp_item);   // wait for expected
      act_fifo.get(act_item);   // wait for actual
      check_items(exp_item, act_item);
    end
  endtask
endclass

// In environment connect_phase:
ref_model.ap.connect(m_scb.exp_fifo.analysis_export);
m_agent.m_monitor.ap.connect(m_scb.act_fifo.analysis_export);
Key takeaway: Analysis ports are fire-and-forget broadcasts — one write reaches all connected exports. Use TLM FIFOs to decouple producer/consumer timing in scoreboards. The driver↔sequencer connection uses the specialised seq_item_port/export, not a generic TLM port.

Callbacks and UVM Events

Module 11 · ~8 min · Advanced
Outcome: Add callbacks to components to enable error injection without modifying verified code, and use UVM events and barriers to synchronise parallel processes.
UVM Callbacks — modify behaviour without subclassing

Callbacks let you inject behaviour into a component at specific hook points — pre_drive, post_drive, pre_randomize — without subclassing or modifying the original verified component. The component declares the hooks; the test registers callback objects that fill them in.

callback class + registration + usage
// Step 1: Declare callback class with hook methods
class apb_driver_cbs extends uvm_callback;
  `uvm_object_utils(apb_driver_cbs)
  // Default implementations do nothing — override in subclass
  virtual task pre_drive(apb_driver drv, apb_seq_item item); endtask
  virtual task post_drive(apb_driver drv, apb_seq_item item); endtask
endclass

// Step 2: Register callback type in the component
class apb_driver extends uvm_driver#(apb_seq_item);
  `uvm_register_cb(apb_driver, apb_driver_cbs)  // register hook
  task drive_item(apb_seq_item item);
    `uvm_do_callbacks(apb_driver, apb_driver_cbs, pre_drive(this, item))
    // ... actual driving code ...
    `uvm_do_callbacks(apb_driver, apb_driver_cbs, post_drive(this, item))
  endtask
endclass

// Step 3: Implement error injection callback
class apb_error_inject_cb extends apb_driver_cbs;
  `uvm_object_utils(apb_error_inject_cb)
  virtual task pre_drive(apb_driver drv, apb_seq_item item);
    // Corrupt every 5th address — no changes to driver needed
    if ($urandom_range(0,4) == 0) item.addr = item.addr ^ 32'hFFFF;
  endtask
endclass

// Step 4: Add callback instance in the test
apb_error_inject_cb err_cb = apb_error_inject_cb::type_id::create("err_cb");
uvm_callbacks#(apb_driver, apb_driver_cbs)::add(
  m_env.m_agent.m_driver, err_cb);
UVM Events — synchronise between parallel processes
uvm_event and uvm_event_pool
// ── Declare and use a named event from the global event pool ─
uvm_event e = uvm_event_pool::get_global("seq_done");

// In producer (sequence body):
seq_body_completes: e.trigger();        // fires event

// In consumer (another sequence or component):
e.wait_trigger();                       // blocks until fired
e.wait_trigger_data(data_obj);          // blocks + receives payload

// ── UVM Barrier — synchronise N processes ─────────────────────
uvm_barrier barrier = new("barrier");
barrier.set_threshold(3);   // wait until 3 processes call wait_for()

// In each of the 3 parallel sequences:
barrier.wait_for();          // all 3 release simultaneously

// ── Heartbeat — detect stuck components ───────────────────────
uvm_heartbeat hb;
uvm_event     hb_e = uvm_event_pool::get_global("heartbeat");
hb = new("hb", this, hb_e);
hb.add(m_driver);            // register component
hb.set_mode(UVM_ANY_ACTIVE); // any registered component must pulse
hb.start(hb_e);              // timeout if no pulse within threshold

// In the monitored component — pulse the heartbeat:
hb_e.trigger();              // call periodically inside run_phase
Callback in a sequence — resetting behaviour without modifying base
callback registered to a sequence
class apb_seq_cbs extends uvm_callback;
  virtual task post_body(apb_write_seq seq); endtask
endclass

class apb_write_seq extends uvm_sequence#(apb_seq_item);
  `uvm_register_cb(apb_write_seq, apb_seq_cbs)
  task body();
    // ... sequence body ...
    `uvm_do_callbacks(apb_write_seq, apb_seq_cbs, post_body(this))
  endtask

Key takeaway: Callbacks are extension hooks in verified components — use them for error injection, coverage taps, and protocol violations without touching the base component. UVM events coordinate parallel sequences. Barriers synchronise N concurrent processes. Heartbeats detect hung drivers or monitors.

RAL — Register Abstraction Layer

Module 12 · ~10 min · Advanced
Outcome: Build a RAL register model for a peripheral, connect it to the DUT via an adapter, and use frontdoor/backdoor access to read/write registers and run built-in register tests.
Why RAL exists

Without RAL, every register test writes raw hex values to raw addresses. When the register map changes (and it always changes), you update every test that references those registers. RAL replaces this with a named model — reg_model.ctrl.write() instead of axi_write(32'h4001_0004, 32'h0000_0001).

Building the register model
register, register block, register map
// ── Step 1: Define individual registers ───────────────────────
class ctrl_reg extends uvm_reg;
  `uvm_object_utils(ctrl_reg)

  uvm_reg_field enable;   // bit 0
  uvm_reg_field mode;     // bits [3:1]
  uvm_reg_field reserved; // bits [31:4] — read-only, tied 0

  function new(string name = "ctrl_reg");
    super.new(name, 32, UVM_NO_COVERAGE);
  endfunction

  function void build();
    enable   = uvm_reg_field::type_id::create("enable");
    mode     = uvm_reg_field::type_id::create("mode");
    reserved = uvm_reg_field::type_id::create("reserved");
    // configure(parent, size, lsb_pos, access, volatile, reset, has_reset)
    enable.configure  (this, 1,  0, "RW", 0, 1'b0, 1);
    mode.configure    (this, 3,  1, "RW", 0, 3'b0, 1);
    reserved.configure(this, 28, 4, "RO", 0, 28'b0, 1);
  endfunction
endclass

// ── Step 2: Define the register block (full peripheral map) ───
class apb_reg_block extends uvm_reg_block;
  `uvm_object_utils(apb_reg_block)

  ctrl_reg   ctrl;    // offset 0x00
  status_reg status;  // offset 0x04
  data_reg   data;    // offset 0x08

  uvm_reg_map default_map;

  function void build();
    ctrl   = ctrl_reg::type_id::create("ctrl");
    status = status_reg::type_id::create("status");
    data   = data_reg::type_id::create("data");
    ctrl.build();  status.build();  data.build();
    ctrl.configure  (this, null, "ctrl");
    status.configure(this, null, "status");
    data.configure  (this, null, "data");

    // Create register map — base addr, bus width, endian
    default_map = create_map("default_map", 32'h4000_0000, 4, UVM_LITTLE_ENDIAN);
    default_map.add_reg(ctrl,   32'h00, "RW");
    default_map.add_reg(status, 32'h04, "RO");
    default_map.add_reg(data,   32'h08, "RW");
    lock_model();  // freeze map after build
  endfunction
endclass
Adapter — connects RAL to your bus sequencer
APB register adapter
class apb_reg_adapter extends uvm_reg_adapter;
  `uvm_object_utils(apb_reg_adapter)

  // Convert RAL generic access → APB sequence item
  function uvm_sequence_base reg2bus(const ref uvm_reg_bus_op rw);
    apb_seq_item item = apb_seq_item::type_id::create("item");
    item.write = (rw.kind == UVM_WRITE);
    item.addr  = rw.addr;
    item.data  = rw.data;
    return item;
  endfunction

  // Convert APB response → RAL generic response
  function void bus2reg(uvm_sequence_item bus_item, ref uvm_reg_bus_op rw);
    apb_seq_item item;
    $cast(item, bus_item);
    rw.kind   = item.write ? UVM_WRITE : UVM_READ;
    rw.addr   = item.addr;
    rw.data   = item.data;
    rw.status = UVM_IS_OK;
  endfunction
endclass
Using the RAL model in a test
frontdoor and backdoor register access
// In test build_phase — create and connect the model
apb_reg_block reg_model = apb_reg_block::type_id::create("reg_model");
reg_model.build();
apb_reg_adapter adapter = apb_reg_adapter::type_id::create("adapter");
reg_model.default_map.set_sequencer(
  m_env.m_agent.m_sequencer, adapter);

// ── Frontdoor write — goes through the bus (driver drives it)
uvm_status_e status;
reg_model.ctrl.write(status, 32'h0000_0003);  // enable=1, mode=1
reg_model.ctrl.read (status, read_data);

// ── Field-level access — read/write specific fields only
uvm_reg_data_t val;
reg_model.ctrl.enable.write(status, 1'b1);
reg_model.ctrl.mode.read(status, val);

// ── Backdoor write — directly updates HDL without driving bus
// Requires HDL path set during build
reg_model.ctrl.write(status, 32'h7, UVM_BACKDOOR);

// ── mirror() / update() — sync model with DUT ────────────────
reg_model.ctrl.mirror(status, UVM_CHECK);  // read DUT, compare to model
reg_model.ctrl.update(status);             // write model value to DUT
