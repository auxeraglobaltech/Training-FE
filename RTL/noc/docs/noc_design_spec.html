1 · Introduction & Scope

The 2×2×2 NoC is a small but complete on-chip interconnect that connects two AXI4 initiators (masters M0, M1) to four targets: two native AXI4 slaves (S0, S1) and two APB4 peripherals (P0, P1) reached through an integrated AXI→APB bridge. It performs the four classic interconnect jobs on every transaction:

JobMeaning in this DUTBlock
RouteDecode the address to S0/S1/P0/P1, or raise a decode error.noc_axi_decoder (inlined in noc_top)
ArbitrateWhen both masters target one slave, choose order by priority then round-robin.noc_arbiter
ConvertTranslate AXI bursts into APB single transfers and map responses back.axi2apb_bridge
OrderHonour AXI ordering and outstanding limits across the fabric; never hang.noc_top read tracker / response path

The DUT is intentionally self-contained: the RTL depends only on the package noc_pkg and never on the testbench. It is the subject of a companion Verification Plan.

2 · Top-Level Architecture

Two AXI master ports feed the fabric. The fabric decodes each request to one of five target servers (S0, S1, P0-bridge, P1-bridge, and a DECERR responder), arbitrates the two masters per server, and muxes responses back to the originating master.

3 · Address Map

The address map is the single source of truth, defined once in noc_pkg and reused by the decoder and (a mirror of) the scoreboard. Ranges are non-overlapping and power-of-two aligned.

TargetTypeBaseEnd (inclusive)SizeDecode result
S0AXI0x0000_00000x0FFF_FFFF256 MBTGT_S0
S1AXI0x1000_00000x1FFF_FFFF256 MBTGT_S1
P0APB0x2000_00000x2000_FFFF64 KBTGT_P0
P1APB0x2001_00000x2001_FFFF64 KBTGT_P1
Any other address (e.g. 0x3000_0000) is unmapped → TGT_NONE → the fabric returns DECERR.
// noc_pkg.sv — the decode reference function (reused by RTL and DV)
function automatic target_e decode(input logic [31:0] addr);
  if      (addr inside {[S0_BASE:S0_END]}) decode = TGT_S0;
  else if (addr inside {[S1_BASE:S1_END]}) decode = TGT_S1;
  else if (addr inside {[P0_BASE:P0_END]}) decode = TGT_P0;
  else if (addr inside {[P1_BASE:P1_END]}) decode = TGT_P1;
  else                                     decode = TGT_NONE; // unmapped → DECERR
endfunction

5 · Address Decode & Routing

Each master's AW and AR addresses are decoded independently and combinationally by the decode() function. The decoded target gates the request so that only the matching target server sees a valid request:

arv_s0[i] = m_arvalid[i] & (dec_ar[i]==TGT_S0) & ar_allow[i];  // i = master 0/1
arv_p0[i] = m_arvalid[i] & (dec_ar[i]==TGT_P0) & ar_allow[i];
... (one gated valid per target, including the DECERR responder)

Routing is per-port: M0 may route to S1 in the same cycle M1 routes to P0 (no interaction). If both decode to the same target, the conflict passes to that target's arbiter (§6). An unmapped address routes to the DECERR responder, never to a slave.

4 KB boundary. An AXI INCR burst must not cross a 4 KB boundary, which guarantees a single burst maps to a single target. Burst-boundary legality is the stimulus generator's responsibility; noc_pkg::crosses_4k() is provided for checkers.

6 · Arbitration (noc_arbiter)

Every shared resource (each target's write channel and read channel) is fronted by a two-requester arbiter. The scheme is strict priority with a round-robin tie-break:

ConditionGrant
Only one requesterGrant it
Both, different priority (AxQOS)Grant the strictly higher priority — strict, may starve the lower
Both, equal priorityRound-robin: grant whoever was not served last

6.1 Grant-lock (protocol stability)

A purely combinational grant could change while a downstream AWVALID/ARVALID is asserted but not yet accepted — e.g. a higher-priority master arriving mid-handshake — which violates AXI payload stability. The arbiter therefore locks a presented grant until it is accepted (update pulse). Once locked, the same grantee/payload is held, then released on accept.

always_ff @(posedge clk or negedge rstn)
  if (!rstn)                       {locked,last} <= {1'b0,1'b1};
  else begin
    if (update)                    locked <= 1'b0;             // released on accept
    else if (gnt_valid && !locked) {locked,lock_idx} <= {1'b1, gnt_idx};
    if (update && gnt_valid)        last   <= gnt_idx;          // RR pointer advances
  end

7 · AXI Slave Port (noc_axi_slave_port)

Drives one native AXI slave (S0 or S1). It is a thin, mostly-combinational forwarder around two arbiters.

Write path

  • A write arbiter grants M0/M1; a small FSM forwards the burst AW → W… → B to the slave (one write in flight per port — see §11).
  • The slave-side ID is remapped to {master_idx, orig_id}; the original ID is returned to the master on B.

Read path (multi-outstanding, out-of-order)

  • The read arbiter forwards ARs to the slave back-to-back — many reads can be in flight.
  • The slave returns R bursts tagged with the remapped ID; each beat is demuxed back to its master purely by the ID's top bit. The slave guarantees per-ID ordering and contiguous bursts, so at any beat exactly one master is addressed.

8 · AXI→APB Bridge (axi2apb_bridge)

Reconciles AXI (5 channels, bursts, IDs) with APB (single, fully-ordered transfer). One transaction at a time is serialised onto APB; writes are chosen before reads when both are pending.

ConversionBehaviour
Burst → singlesAn N-beat INCR burst becomes N APB transfers with incrementing addresses (step = 2AxSIZE).
Write responseExactly one B per write burst; any PSLVERR on a beat aggregates to BRESP = SLVERR.
Read responseEach R beat carries its transfer's RRESP (PSLVERR → SLVERR).
Write strobesWSTRB forwarded as PSTRB (APB4).

9 · DECERR Responder (noc_decerr_port)

Unmapped accesses are routed here. It behaves like a target with no slave behind it: it accepts the request (swallowing all write beats), then returns a clean error so the master always recovers and the fabric never hangs.

  • Write: consume AW and all W beats → single B = DECERR.
  • Read: AR → (ARLEN+1) R beats, each RDATA = 0, RRESP = DECERR, RLAST on the final beat.
A global testbench watchdog turns any hang (e.g. the DECERR_OMIT bug) into a UVM_ERROR rather than a frozen simulation.

10 · Outstanding, Ordering & ID Remap

10.1 ID remap

When the fabric issues to an AXI slave it prepends the master index to the AXI ID, forming a 5-bit slave-side ID. Responses (which may return out of order across IDs) carry that tag, so the response path routes each one back to the correct master by the top bit, then strips it to restore the original ID.

10.2 Read outstanding tracker

Per master, the fabric tracks per-ID outstanding read counts and a total (capped at MAX_OUTSTANDING). A new read is gated (ar_allow) when:

ar_allow[i] = (rtotal[i] < MAX_OUTSTANDING)                              // capacity
            & ~( out_cnt[i][arid] != 0 & out_tgt[i][arid] != dec_ar[i] ); // same-ID, different target

The second term enforces the cross-slave same-ID ordering contract (§11) by serialising a same-ID read that targets a different slave than an already-outstanding same-ID read.

10.3 R-burst-lock mux

Because reads are multi-outstanding, several servers may have R data for one master at once. A per-master mux locks onto the selected server for the whole burst (until RLAST) and gates RREADY to only that server, so read bursts never interleave at the master port.

11 · Transaction Contracts

PropertyContract
ReadsMultiple outstanding, out-of-order across IDs; capped at MAX_OUTSTANDING per master.
