1 · Verification Goals & Surface

To sign off the NoC (see the Design Specification) the environment must prove:

AreaThe one thing to prove
ConnectivityAll 2×4 master→target paths work, reads and writes.
DecodeIn-range routes to the right target; out-of-range returns DECERR, reaches no slave, never hangs.
ArbitrationStrict priority honoured; round-robin tie-break on equal priority; legal grants only.
ConversionAXI bursts → correct APB singles; PSLVERR → SLVERR; one B per write burst.
ConcurrencyOrdering preserved under simultaneous two-master load; no deadlock.
RobustnessError injection handled cleanly; protocol legal on every port.

2 · Strategy

The environment separates deterministic correctness from non-deterministic policy:

  • Scoreboard (deterministic): data correctness, routing (which target was reached), response codes, and DECERR — checked exactly against a golden memory and the reused decode() model. It accepts any legal arbitration interleaving; it never tries to predict which master wins first.
  • Assertions (policy & protocol): AXI/APB handshake legality and arbitration policy (priority-honoured, mutual exclusion) — checked cycle-accurately by SVA.
  • Coverage: records that the routing matrix and priority relationships were actually exercised.
Mixing these up — e.g. making the scoreboard model the arbiter pointer to predict arrival order — is the classic way NoC scoreboards drown in false failures. Keeping arbitration order out of the scoreboard and in the assertions is the central design choice here.

Reactive responders are where realism is injected. Random back-pressure, variable latency, and on-command errors are what stress the fabric's buffering, ordering, and error paths. A slave that always answers instantly with OKAY would hide most fabric bugs.

5 · Routing-Aware Scoreboard

For every completed master transaction the scoreboard asks two questions: did it reach the correct target? and was the data correct there?

  1. Predict target by reusing noc_pkg::decode(addr) — the same model the RTL uses.
  2. Data: writes update a golden memory per target (strobed); reads are predicted from that memory and compared beat-by-beat.
  3. Response: expect OKAY for mapped targets, DECERR for unmapped, or SLVERR for a target a test has marked as error-injecting.
  4. Routing: the slave-side arrival monitors confirm each arrival's address decodes to that target — catching a mis-route that a data-only check would miss, and confirming an unmapped access reaches no slave.

Reported at end of test: writes, reads, decerr, per-target arrival counts, and total errors; a clean run prints SCOREBOARD PASSED.

6 · Assertions (SVA)

Protocol assertions live inside the interfaces (Xcelium forbids binding a module into an interface); the arbiter checker is bound to every noc_arbiter.

GroupLocationProperties
AXI protocolaxi_ifVALID held until READY (all 5 channels); payload stable while a transfer is stalled (AW/AR/W/B/R).
APB protocolapb_ifsetup→access sequence; address/control stable during access; PENABLE only with PSEL; PENABLE drops after a completed transfer.
Arbitrationarb_sva → noc_arbiterMutual exclusion (!(gnt0&&gnt1)); grant-valid iff a request; strict priority honoured (higher QoS wins under contention).
Liveness (opt)arb_sva (+define+ARB_CHECK_LIVENESS)Bounded-wait — expected to fail under strict priority, demonstrating the starvation hazard. OFF by default.

9 · Test Cases — Intent & Checks

9.1 Sanity / Connectivity

Intent: prove the environment and the 2×4 path set work end-to-end. Stimulus: connectivity_seq — W then R to each target (incl. a 4-beat burst) plus an unmapped W and R. Pass: all data matches the golden memory; mapped → OKAY, unmapped → DECERR; arrivals seen at the predicted targets only.

9.2 Decode boundaries

Intent: off-by-one decode bugs live at range edges. Stimulus: decode_boundary_seq hits the last in-range word of S0/S1/P0/P1 and addresses just above P1, plus 0x3000_0000 and 0xFFFF_FFFC. Pass: in-range route correctly; out-of-range return DECERR and reach no slave.

9.3 Concurrency

Intent: the hard ordering/arbitration behaviour only appears with both masters in flight. Stimulus: concurrent_mixed_vseq forks independent random traffic on M0 and M1. Pass: scoreboard clean accepting any legal interleaving; no AXI/APB/arb assertion fires; no deadlock (watchdog silent). (Observed: 100 writes + 100 reads, arrivals across all four targets, 0 errors.)

9.4 Round-robin arbitration

Intent: equal-priority contention must produce legal, fair alternation. Stimulus: both_storm_vseq drives both masters at S0 with equal QoS, using disjoint address windows so there is no cross-master same-address data hazard (contention is at the slave port, not the address). Pass: arb_sva mutual-exclusion/legality hold; scoreboard clean.

9.5 Strict priority

Intent: the higher-priority master must win every contended grant. Stimulus: both storm S0, M1 QoS high / M0 QoS low. Pass: ap_prio_m1 never fires (M1 always granted when both request and M1 is higher), scoreboard clean. Note: strict priority may starve M0 by design — this is intended policy, demonstrable via the optional bounded-wait assertion.

9.6 Bridge / protocol conversion

Intent: burst→single conversion and error mapping. Stimulus: storm_seq to P0 with the P0 responder asserting PSLVERR on every transfer; the scoreboard is told to expect SLVERR for P0. Pass: every P0 write/read returns SLVERR (one B per write burst); APB protocol assertions hold. The clean (no-error) bridge path is covered by sanity/random/concurrency.

11 · How to Run

Tooling is Cadence Xcelium; the interactive shell is csh/tcsh. Source the environment, then run from RTL/noc/sim:

source ~/cshrc                       # puts xrun (Xcelium 2503) + UVM CDNS-1.2 on PATH

make elab                            # compile + elaborate only (fast check)
make sim TESTNAME=noc_sanity_test    # run a UVM test
make sim TESTNAME=noc_concurrency_test WAVES=1 SEED=42
make sim TESTNAME=noc_rr_arb_test COV=1            # + functional/code coverage
make smoke                           # non-UVM datapath + OOO smoke

# fault injection (bug caught by the env):
make sim TESTNAME=noc_bridge_test BUG=PSLVERR_SWALLOW

# run the whole suite (csh):
foreach t (noc_sanity_test noc_decode_test noc_random_test noc_concurrency_test \
           noc_rr_arb_test noc_priority_test noc_bridge_test)
  make sim TESTNAME=$t |& grep -E "RESULT|UVM_ERROR :|SCOREBOARD"
end

Each run lands in RTL/noc/sim/runs/run_<timestamp>_seed<N>/xrun.log. Pass/fail:

grep -E "TEST PASSED|TEST FAILED|UVM_ERROR :" runs/run_*/xrun.log | tail

12 · Results & Limitations

Result: all seven UVM tests and the datapath smoke pass on the golden RTL with UVM_ERROR : 0 and no protocol/arbitration assertion failures. The concurrency test alone drives 200 transactions across both masters and all four targets cleanly. The fault campaign confirms injected bugs are caught.

Notable finding during bring-up

The embedded AXI stability assertions surfaced a real RTL issue: a purely combinational arbiter could flip its grant mid-handshake under contention (an AWVALID/ARVALID stability violation). The fix — an arbiter grant-lock that holds a presented grant until accepted — was added and validated under the concurrency test.

Known limitations / future work

  • UVM-side OOO depth. The reactive responders are in-order, so the UVM suite exercises cross-master contention, routing, bridge, and decode rather than single-master out-of-order depth. Single-master OOO is proven by the smoke [OOO] check. Future: add out-of-order responders + a pipelined multi-outstanding master driver.
  • Statistical fairness. Completion-share is ~50/50 by construction with fixed-count sequences, so arbitration is verified by the arb_sva assertions rather than a fairness statistic. Future: windowed grant-count measurement to quantify fairness and tighten RR_FREEZE detection.
  • Coverage closure. The model is in place; closure (driving route_x/qos_x to 100% and reviewing holes) is a follow-on activity with COV=1 regressions.
  • Writes are one-outstanding per master by design; write-pipelining (with W-data interleaving) is out of scope for this build.
