1 · Strategy: Two Layers, Hybrid Checking

A GPGPU's "stimulus" is a program. The environment therefore has two orthogonal test layers, composed through Makefile knobs:

  • Layer A — software testcases (C or asm) that run ON the core. Bare-metal RISC-V programs in dv/sw/tests/, built with the Vortex GNU toolchain into $readmemh images. Selected with KERNEL=<name>.
  • Layer B — SV/UVM testcases that DRIVE the core. The env boots the selected image over DCR, serves memory, and checks the outcome. Selected with TESTNAME=<uvm_test> (plus the pre-UVM directed vx_smoke).
  • Hybrid = a UVM run whose scoreboard additionally cross-checks the kernel's memory output against a DPI-C golden model (HYBRID=1), and/or the same ELF replayed on the simx cycle-approximate golden simulator (make cosim).

3 · Agents

3.1 Memory agent (vx_mem_agent, ×2 — one per bank)

Reactive slave. There is no memory "stimulus" to generate: the DUT is the master. Components:

  • vx_mem_model (uvm_object, one instance shared by both banks via config_db): sparse byte associative array; load_hex() ($readmemh image), rd_byte/rd_word() for end-of-test checking; global n_rd/n_wr counters.
  • vx_mem_responder: always-ready request acceptance; writes commit immediately (byteen-masked); reads are queued with a due-cycle (RSP_LATENCY = 4) and returned in order with the request's tag, honoring mem_rsp_ready backpressure.
  • vx_mem_monitor: publishes every accepted request as a vx_mem_txn (rw, bank, computed byte address per the interleave formula, 512-bit data, byteen, tag) to the scoreboard and coverage.

3.2 DCR agent (vx_dcr_agent)

Active master. Standard sequencer/driver/monitor stack over vx_dcr_if. The driver issues single-cycle write strobes; for reads it waits for rsp_valid and returns the data in the response transaction before item_done. The monitor feeds DCR coverage.

3.3 Control agent (vx_ctrl_agent)

No sequencer — two task APIs used directly by tests: pulse_start() (1-cycle start) and wait_done(idle_confirm), which declares completion only when busy stays low for idle_confirm = 100 consecutive cycles (the KMU deasserts busy between launch phases — a single-edge wait false-passes).

5 · Scoreboard — Four Check Layers

Each layer defeats a specific failure/false-pass mode; a run can enable any subset.

④simx co-simulation: make cosim runs the same ELF on the simx golden simulator; its process rc is the exit word's low byte (0 = PASS).make cosim targetThe program semantics agree with upstream's reference simulator — catches env-level bugs (boot, memory model) that RTL-only checking can't.
The exit contract exists because the first smoke run "passed" with zero instruction fetches: busy blipped, memory was never read, and address 0x8348 read back 0 — which the naive check accepted. Layers ① were added specifically to make that impossible.

8 · Software Build Flow

dv/sw/Makefile (toolchain at /home/user1/vortex/riscv32-gnu-toolchain):

<test>.c/.S ──riscv32-unknown-elf-gcc──▶ .elf ──objcopy──▶ .bin ──bin2hex.py──▶ .hex (@80000000)
   -march=rv32imf_zicsr -mabi=ilp32 -O2 -ffreestanding -nostdlib          └──▶ .dis (objdump)
   -T common/link.ld  common/crt0.S
vecadd_expected.py ──▶ vecadd.expected.hex   (golden file for layer ②)

crt0.S sets sp = 0x8010_0000, zeroes BSS, calls main, writes the exit contract words, then wsync + tmc x0. link.ld places .init first at 0x8000_0000 (1 MB RAM window).

9 · How to Run

From RTL/vortex/dv/sim (csh, source ~/cshrc for Xcelium 25.03):

make -C ../sw                                   # build all kernels (.elf/.hex/.dis + expected files)

make elab                                       # compile + elaborate only
make vx_smoke                                   # directed SV smoke (asm/nop)
make sim TESTNAME=vx_base_test                  # UVM, default KERNEL=asm/nop
make sim TESTNAME=vx_asm_test    KERNEL=asm/self_check
make sim TESTNAME=vx_base_test   KERNEL=asm/divergence
make sim TESTNAME=vx_vecadd_test KERNEL=c/vecadd            # +EXPECTED auto-added
make sim TESTNAME=vx_base_test   KERNEL=c/vecadd HYBRID=1   # + DPI-C reference (layer ③)
make sim TESTNAME=vx_base_test   KERNEL=c/fp_ops COV=1 WAVES=1
make cosim KERNEL=c/vecadd                      # simx golden replay (layer ④)

10 · Pass/Fail Criteria

  • PASS = simulation completes (no 2M-cycle watchdog), UVM_ERROR : 0, and every enabled check layer reports its RESULT: … PASSED line (make cosim: COSIM: [OK]).
  • FAIL = any UVM_ERROR: missing done magic, zero fetches, no exit write, non-zero exit code (the code identifies the failing self-check), golden-file or DPI-ref word mismatch (address + got/expect printed), or watchdog timeout.
