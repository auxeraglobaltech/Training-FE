1 · How to Read This Catalog

Each test below is a structured entry, and within it each distinct scenario (a sub-case with its own stimulus and expected result) is broken out separately. The fields are:

FieldMeaning
IDStable identifier (TC-nn / scenario S-nn.k) for traceability.
ObjectiveThe behaviour the case is designed to prove.
PreconditionState required before stimulus — always at least "calibration complete".
StimulusExact addresses, data, and byte-select patterns driven.
ExpectedThe device/model response the scenario should produce.
ChecksWhich checkers fire (scoreboard compare, coverage sample).
Pass/FailThe concrete pass condition.
CommandThe exact command line to run the case.

2 · Common Preconditions & Mechanics

These apply to every test; individual entries do not repeat them.

  • Environment. tb_top_wb_uvm builds the clocks (controller 10 ns, DDR3 2.5 ns), ddr3_top (BIST_MODE=0, AUX_WIDTH=16, ODELAY=0, MICRON_SIM=1), and the Micron x16 model, and publishes wb_if via the config DB.
  • Calibration gate. Every test calls wait_calib() — it blocks on vif.calib_complete === 1'b1 (≈8.93 µs with MICRON_SIM) before any traffic. The driver also refuses to issue until calibration is high.
  • Transaction model. One Wishbone transfer = one 128-bit word at a 24-bit word address {row[23:10], bank[9:7], col[6:0]}. The driver is single-outstanding and pipelined: assert the request until stb && !stall, then collect ack (read data with it).
  • Reference model. The scoreboard mirrors every accepted write into gm[addr] applying the sel mask byte-by-byte, and compares every read to it (unwritten = 0). Unwritten addresses read 0.
  • Result. A test passes when the scoreboard reports SCOREBOARD PASSED and the test reports ** TEST PASSED ** with UVM_ERROR : 0 and UVM_FATAL : 0.
  • Where to run. All commands run from RTL/uberddr3/dv/sim after source ~/cshrc.

3 · TC-01 · ddr_sanity_test

TC-01Basic write/read data integrity

ObjectiveProve a written 128-bit word is returned unchanged by a subsequent read, at addresses that span different banks and rows.
Sequenceddr_sanity_seq (5 × wr_then_rd).
PreconditionCalibration complete; golden memory empty.
ChecksScoreboard read-compare on each read; coverage samples direction/bank/sel on every transfer.
Pass/FailAll 5 reads match the values just written; SCOREBOARD PASSED.

The sequence performs five write-then-read pairs. Each pair is a scenario; the data are fixed constants so a mismatch is unambiguous.

S-01.1 — base address, bank 0.
Stimulus: write addr=0x00_0000, data=DEADBEEF_00112233_44556677_8899AABB, full sel; then read 0x00_0000.
Expected: read returns the same 128-bit value. Check: scoreboard equality.
S-01.2 — adjacent column.
Stimulus: write addr=0x00_0001, data=01234567_89ABCDEF_FEDCBA98_76543210; read back.
Expected: value preserved; proves the neighbouring column is independent of S-01.1.
S-01.3 — different bank.
Stimulus: write addr=0x00_0080 (bank field bit set), data=A5A5A5A5_5A5A5A5A_F0F0F0F0_0F0F0F0F; read back.
Expected: value preserved across an activate to another bank.
S-01.4 — different row.
Stimulus: write addr=0x00_8000 (higher row bits), data=11111111_22222222_33333333_44444444; read back.
Expected: value preserved across a row activate/precharge.
S-01.5 — high row region.
Stimulus: write addr=0x10_0000, data=CAFEBABE_DEADC0DE_8BADF00D_FEEDFACE; read back.
Expected: value preserved in a distant row region.
make sim TESTNAME=ddr_sanity_test

4 · TC-02 · ddr_bytesel_test

TC-02Byte-select (masked) writes

ObjectiveProve that a masked write updates only the byte lanes whose sel bit is set, leaving all other bytes of the 128-bit word intact (PSTRB semantics).
Sequenceddr_bytesel_seq: one full baseline write to addr=0x00_0040, then 6 partial writes (each followed by a read) using different select patterns.
PreconditionCalibration complete; the baseline establishes a known all-ones word at the target.
ChecksScoreboard applies the same mask to its golden word and compares each read; coverage records sel_cp bins (full/partial/single).
Pass/FailEvery read equals the masked merge of baseline + partial writes; SCOREBOARD PASSED.

All scenarios target the same address 0x00_0040 so each partial write merges over the previous content. The merge rule is: for byte b, if sel[b]=1 take the new data byte, else keep the stored byte.

S-02.0 — baseline. Write 0x00_0040 = FFFF…FFFF (sel=0xFFFF, all 16 bytes). Establishes a known starting word.
S-02.1 — single low byte. sel=0x0001 (byte 0 only): only the least-significant byte changes; bytes 1–15 stay 0xFF. Read merges accordingly. (coverage: single)
S-02.2 — single high byte. sel=0x8000 (byte 15 only): only the most-significant byte changes. (coverage: single)
S-02.3 — low half. sel=0x00FF (bytes 0–7): the low 64 bits update, the high 64 bits are unchanged. (coverage: partial)
S-02.4 — high half. sel=0xFF00 (bytes 8–15): the high 64 bits update, low 64 bits unchanged. (coverage: partial)
S-02.5 — alternating bytes. sel=0xA5A5: a scattered byte pattern updates; the complementary bytes are retained. (coverage: partial)
S-02.6 — interleaved nib's bytes. sel=0x0F0F: another scattered pattern. Each partial write uses fresh random data, so the check depends entirely on correct masking. (coverage: partial)
Historical note: an earlier c_sel constraint forced sel=0xFFFF on writes and made the partial-write scenarios impossible; it was removed and sequences now set sel directly. The test passes only because the device and the golden model apply the identical mask.
make sim TESTNAME=ddr_bytesel_test

5 · TC-03 · ddr_walk_test

TC-03Address decode walk — banks, rows, columns

ObjectiveProve the {row,bank,col} word-address decode is correct and aliasing-free by walking each field independently; each location holds a value that encodes its index.
Sequenceddr_walk_seq: a bank walk, a row walk, and a column walk, each wr_then_rd.
PreconditionCalibration complete.
ChecksScoreboard compare per location; coverage fills bank_cp b[0..7] and the dir × bank cross.
Pass/FailEvery walked location reads back its encoded value with no cross-contamination; SCOREBOARD PASSED.
S-03.1 — bank walk (8 scenarios).
For bk = 0…7: addr = (bk<<7) | 0x5, data = 0xBA0000_00 | (bk<<24) | bk. Each of the 8 banks is activated and written with a bank-tagged value, then read. Expected: each bank returns its own value — proves bank bits [9:7] select distinct banks and the column offset (0x5) is consistent. Fills all 8 bank_cp bins.
S-03.2 — row walk (8 scenarios).
For r = 0…7: addr = (r<<13), data = 0xF0F0_0000 | r. Steps the address by whole rows. Expected: each row location returns its own value — proves the high address bits map to row activates and that an activate/precharge of one row does not disturb another.
S-03.3 — column walk (16 scenarios).
For c = 0…15: addr = 0x01_0000 | c, data = 0xC01_00000 | c. Walks columns within a single row. Expected: each column returns its own value — proves the low address bits index columns within an open row without aliasing.
make sim TESTNAME=ddr_walk_test

6 · TC-04 · ddr_random_test

TC-04Randomized mixed read/write traffic

ObjectiveStress the controller's scheduling and read-after-write paths with randomized, mixed-direction traffic over a bounded address window, while keeping every read checkable.
Sequenceddr_random_seq with default num=50 transactions.
PreconditionCalibration complete; seed set by SEED (random unless given).
StimulusFor each iteration: pick addr = $urandom_range(0, 0xFFFF). With ~50% probability — or whenever the address has never been written — issue a write of fresh random 128-bit data and record it in a local shadow map; otherwise issue a read of a previously-written address. This guarantees reads always target written locations.
ExpectedEach read returns the last value written to that address; the device's reordering/refresh is transparent.
ChecksScoreboard golden-memory compare on every read; coverage fills the dir × bank cross and the partial/full select bins over the random window.
Pass/FailZero scoreboard mismatches across all reads; SCOREBOARD PASSED.

Scenario S-04.1 — mixed random stream. The single randomized scenario is reproducible by seed. The shadow map inside the sequence is only a stimulus aid (it decides which addresses are safe to read); the checking reference is the independent scoreboard golden memory.

make sim TESTNAME=ddr_random_test # random seed make sim TESTNAME=ddr_random_test SEED=7 # reproducible make sim TESTNAME=ddr_random_test COV=1 # with coverage

7 · TC-05 · ddr_refresh_test

TC-05Data integrity across auto-refresh

ObjectiveProve that periodic auto-refresh is transparent to the user: data written before a refresh is still correct when read long afterwards, across many tREFI (7.8 µs) intervals.
Sequenceddr_random_seq randomized with num == 300 — a long run that necessarily spans multiple refresh cycles — plus a #2000ns drain before dropping the objection.
PreconditionCalibration complete.
StimulusSame mixed random read/write generator as TC-04 but 300 transactions, so simulated time crosses several auto-refresh boundaries while traffic is in flight.
ExpectedEvery read still returns its written value despite intervening refresh commands; no data loss, no stall hang.
ChecksScoreboard compare on all reads; the long duration is the refresh exposure. Coverage continues to accumulate.
Pass/FailZero mismatches over the full 300-transaction run; SCOREBOARD PASSED, ** TEST PASSED **.

Scenario S-05.1 — long traffic crossing refresh. Identical generation to TC-04, the distinguishing factor is duration: 300 transactions guarantee multiple tREFI windows elapse, so a refresh that corrupted or dropped data would surface as a read mismatch.

make sim TESTNAME=ddr_refresh_test

9 · Running & Triage Reference

Run the whole suite (tcsh)

source ~/cshrc
cd RTL/uberddr3/dv/sim
foreach t (ddr_sanity_test ddr_bytesel_test ddr_walk_test ddr_random_test ddr_refresh_test)
  make sim TESTNAME=$t
end

Per-run knobs

KnobExampleEffect
TESTNAMETESTNAME=ddr_walk_testSelects the UVM test.
SEEDSEED=7Fixes +ntb_random_seed for reproducibility.
COVCOV=1Enables functional + code coverage.
WAVESWAVES=1Dumps waveforms for debug.

What a pass looks like

The Makefile greps the run log tail. A passing run shows the calibration message, then:

SCOREBOARD PASSED
** TEST PASSED **
UVM_ERROR :    0
UVM_FATAL :    0

Triage if it fails

  • No calibration / timeout — check the clock periods in tb_top_wb_uvm and that MICRON_SIM=1; the watchdog fires if calib_complete never asserts.
  • SB_DATA mismatch — the log line prints addr, expected, and observed; cross-check against the scenario's stimulus above. For byte-select cases verify the mask merge.
  • Stale module / shim shadowed — Xcelium incremental compile can cache; run make clean then re-run.
  • Compile error in a constant function — ensure the build uses dv/shim/ddr3_controller.sv (via filelist_uvm.f), not the raw upstream rtl/ddr3_controller.v.
