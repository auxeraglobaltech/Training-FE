1 · Introduction & Objectives

This plan describes the UVM environment built around the UberDDR3 controller. The DUT is ddr3_top, exercised through its native pipelined Wishbone user interface; the memory is the bundled Micron x16 DDR3 behavioral model and the 7-series PHY primitives are the repo's behavioral models (+define+SIM_MODEL), so no Xilinx libraries are required.

Verification objectives:

  • Prove the controller calibrates and reaches o_calib_complete in Xcelium.
  • Verify data integrity of writes and reads across banks, rows, and columns.
  • Verify byte-select (masked) writes — only selected bytes update.
  • Verify the {row,bank,col} address decode by walking each field.
  • Verify refresh transparency — data survives auto-refresh over long runs.
  • Exercise randomized mixed traffic and collect functional coverage.
The vendored RTL under RTL/uberddr3/rtl is pristine. The entire environment lives under RTL/uberddr3/dv/; the only RTL touched is the Xcelium constant-function shim dv/shim/ddr3_controller.sv (see the Design Spec §9).

2 · Verification Strategy

The approach is constrained-directed plus randomized, dynamically checked against a reference model:

  • Reference model. A golden associative memory (one 128-bit word per Wishbone address) mirrors every accepted write, applying the byte-select mask exactly as the device does. Each read is compared to it.
  • Directed first. Sanity, byte-select and address-walk sequences pin down specific behaviour with deterministic stimulus, so a failure points straight at a cause.
  • Then randomized. A random read/write sequence over a bounded address window stresses ordering and scheduling; a shadow map ensures reads target previously-written addresses so every read is checkable.
  • Self-checking and self-terminating. Every test raises an objection, waits for calibration, runs its sequence, drains, and drops the objection; the scoreboard reports PASS/FAIL in report_phase.
  • Coverage-instrumented. A subscriber covergroup records direction, bank, and select-pattern coverage (and their cross) so the directed/random mix can be measured.

3 · Testbench Architecture

The top module tb_top_wb_uvm generates the four behavioral clocks, instantiates ddr3_top and the Micron model, exposes the user side through the wb_if virtual interface, publishes the interface through the uvm_config_db, and calls run_test(). The UVM environment drives and observes that interface; the scoreboard and coverage subscribe to the monitor's analysis port.

5 · Checking & Scoreboard

The scoreboard (env/ddr_scoreboard.sv) holds a golden memory bit[127:0] gm[bit[23:0]]. It subscribes to the monitor's analysis port and on each completed transaction:

  • Write — reads the current golden word (0 if never written), overwrites only the byte lanes whose sel[b] bit is set, stores it back, and increments the write count. This exactly models the device's byte-select (PSTRB) behaviour.
  • Read — computes the expected word (golden value, or 0 for an unwritten location — the model reads 0 after calibration) and compares it against rdata. A mismatch raises uvm_error("SB_DATA", …) with the address, expected, and observed data.

In report_phase the scoreboard prints the write/read/error counts and emits SCOREBOARD PASSED when no mismatch occurred, or a uvm_error otherwise. The base test independently reports ** TEST PASSED ** only when the UVM error and fatal counts are both zero.

Because the driver is single-outstanding and the monitor pairs requests to acks in FIFO order, read/write ordering is unambiguous, so the simple per-address golden model is an exact reference.

6 · Functional Coverage

The coverage subscriber (env/ddr_coverage.sv) samples one covergroup per completed transaction:

CoverpointBinsIntent
dir_cp (direction)rd, wrBoth read and write paths exercised.
bank_cp (bank)b[0] … b[7]All 8 DDR3 banks addressed (bank = word-addr[9:7]).
sel_cp (select kind)full, partial, singleFull-word, multi-byte-masked, and single-byte writes all seen.
dir_x_bankcrossReads and writes reach every bank.

Coverage collection is enabled with COV=1 on the make sim line, which adds -coverage all -covoverwrite to the xrun invocation. The ddr_walk_test drives all banks and the ddr_bytesel_test drives every select-kind, so the directed suite alone fills the covergroup; the random test adds cross fill.

8 · How to Build & Run

The user shell is csh/tcsh. From the simulation directory:

source ~/cshrc
cd RTL/uberddr3/dv/sim

# Phase-0 bring-up (no UVM): controller + PHY + Micron model, calibration check
make wb

# UVM tests (Wishbone env)
make sim TESTNAME=ddr_sanity_test
make sim TESTNAME=ddr_bytesel_test
make sim TESTNAME=ddr_walk_test
make sim TESTNAME=ddr_random_test
make sim TESTNAME=ddr_refresh_test

# with functional + code coverage, and/or a fixed seed
make sim TESTNAME=ddr_random_test COV=1 SEED=7

# run the whole suite (tcsh)
foreach t (ddr_sanity_test ddr_bytesel_test ddr_walk_test ddr_random_test ddr_refresh_test)
  make sim TESTNAME=$t
end

make clean

Each run is logged under dv/sim/runs/sim_<timestamp>_<test>_seed<n>/xrun.log; the Makefile greps the tail for RESULT, SCOREBOARD, UVM_ERROR :, and calibration lines.

9 · AXI Path — Known Limitation

UberDDR3 also ships an AXI4 wrapper. We initially targeted it, but under Xcelium the third-party Wishbone-bridge FIFO-fill counter powers up to X (iverilog/Vivado effectively 2-state-initialise it), which blocks AXI writes; calibration and AXI reads work, writes do not complete. After several targeted fixes did not fully resolve it, the environment was built on the controller's native Wishbone interface, which is its real user interface and is fully working. The directed AXI smoke (make axi_smoke) and the X-immune bridge shims remain in the tree as documentation of the investigation. See Design Spec §10.

10 · Exit Criteria

  • All five tests report ** TEST PASSED ** with a clean scoreboard. Met.
  • Calibration reaches o_calib_complete in Xcelium with the bundled behavioral models. Met.
  • Functional coverage: direction, all 8 banks, all select-kinds, and the dir×bank cross hit. Met by the directed+random mix (collect with COV=1).
  • Vendored RTL unmodified except the documented Xcelium constant-function shim. Met.
